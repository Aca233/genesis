# 创世管理面板设计

日期：2026-07-27
状态：已获用户确认

## 1. 目标与边界

为生产站增加完整、低负载、隐私克制的管理员后台。所有 role=admin 且未被封禁的用户拥有相同管理权限。后台用于运营统计、用户与世界管理、任务处置、模型调用分析和审计，不允许通过网页重启应用、数据库或服务器。

首版采用服务端管理台，默认无轮询、SSE 或 WebSocket；页面仅在首次进入、翻页、筛选或手动刷新时查询。

## 2. 信息架构

- /admin：用户、有效会话、世界状态、任务异常、LLM 指标、缓存与系统健康总览。
- /admin/users：搜索用户，查看账号元数据、Discord 绑定、会话数和世界数；封禁/解封、撤销会话、调整管理员角色、永久删除。
- /admin/worlds：按名称、ID、所有者和状态筛选；归档、恢复、永久删除；仅显示元数据。
- /admin/tasks：统一查看创世任务、生成请求和现实改写任务；展示状态、阶段、所有者、世界、持续时间和脱敏错误；支持安全重试、取消和恢复失租任务。
- /admin/llm：按时间、模型、任务、用户和结果筛选调用；展示调用数、成功率、延迟、Token 和缓存指标；只读。
- /admin/audit：展示管理员、动作、对象、原因、结果、时间和 IP。

桌面使用紧凑的“天文台总录”布局；移动端表格转为纵向档案条目，不横向挤压。

## 3. 权限与安全

新增统一服务端守卫 requireAdmin：

1. 必须存在有效会话；
2. user.role 必须为 admin；
3. 被封禁用户不可进入；
4. 非管理员访问管理页面返回 404；
5. 管理 API 对未登录返回 401、非管理员返回 403；
6. 每个页面、查询和变更端点都独立鉴权，不能只依赖前端隐藏。

防锁死规则：管理员不能封禁、删除或取消自己的管理员身份；不能删除或降权最后一个有效管理员。永久删除用户或世界必须输入显示名称/邮箱确认并填写原因。

## 4. 隐私边界

后台永远不展示或检索神谕、对话正文、世界设定正文、人物卡、模型原始输入输出。只显示名称、ID、状态、数量、时间和脱敏错误摘要。任何响应 DTO 都采用显式 select，不查询正文列。

错误脱敏覆盖密钥、Bearer Token、URL 凭据和疑似长 Secret；错误摘要截断。审计 metadata 仅保存状态变化等非正文信息，不保存密码、OAuth Token、API Key 或生成内容。

## 5. 数据结构

新增 AdminAuditLog：

- id
- actorUserId
- action
- targetType
- targetId
- targetLabel
- reason
- success
- requestIp
- metadata
- createdAt

世界归档新增 archivedAt，不复用 draft/playing/concluded 游戏状态。任务取消使用 cancelled 终态；任务重试保留旧故障证据，不静默覆盖历史。

## 6. 性能设计

- 列表默认 25 条，最大 100 条；
- 搜索至少 2 字符；
- 统计查询并行执行，单个失败降级为“暂不可用”；
- 首页使用有限时间窗，不扫描全部 LLM 日志；
- 消息和章节数使用数据库聚合；
- 不建立后台轮询或长连接；
- 操作后只刷新当前区域；
- 系统健康只读 Node uptime/RSS、OS load/memory/swap、固定磁盘、Prisma SELECT 1 和 release/version。

## 7. 操作语义

- 封禁/解封：必须原因，撤销现有会话，并记成功/失败审计。
- 撤销会话：可撤销某用户全部会话。
- 角色：所有 admin 同权；禁止自我降权和移除最后有效管理员。
- 世界：归档/恢复可逆；永久删除需名称确认。
- 用户：永久删除需邮箱确认；由数据库事务执行，遵守关联数据约束。
- 任务：只对允许状态执行取消、恢复或重试；操作必须幂等。
- 系统健康：只读，无命令执行和任意路径输入。

## 8. 错误处理与审计

管理操作先鉴权和校验，再在事务内执行状态变化与审计。对于因校验拒绝或数据库失败的操作，也记录脱敏的失败审计（若数据库可用）。请求 IP 只取经过可信代理配置后的请求头约定。界面以明确中文反馈结果，不暴露堆栈。

## 9. 验收标准

- 普通用户无法发现或进入后台；
- 管理员可访问全部后台页面；
- 危险 API 全部服务端鉴权；
- 自我封禁、自我降权、删除最后管理员被拒绝；
- 确认文本不匹配时永久删除被拒绝；
- 后台响应不存在正文和密钥字段；
- 分页上限不可绕过；
- 脱敏器不泄露 Secret；
- 审计正确记录成功和失败；
- 移动端无横向溢出；
- TypeScript、ESLint、Vitest 与生产构建通过。
