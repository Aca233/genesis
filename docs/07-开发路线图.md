# 07 · 开发路线图

## 1. 当前产品基线

以下规则贯穿后续开发，不再作为可选方案：

- 游戏内无玩家可见章节；`Chapter` 仅为内部检查点；
- 标题为“世界名 + 纪元 + 时间”；
- 每轮轻推演只有一次 Narrator 调用；
- Creator 输入不区分观测与改写；
- 推进时间使用时之仪；
- opening 在创世就绪动画期间开始生成；
- 正文始终可读，后台任务只在输入区显示真实进度。

## 2. Phase 1：Durable 真实进度（已完成）

### 已交付

- `GenerationRequest` durable 阶段：
  `reserved → context_ready → generating → output_stored → applying → completed`；
- chat、settlement、rewrite 统一 `TaskProgressEvent`；
- SSE 订阅与后台 owner 解耦，浏览器断开不终止任务；
- state API 可恢复运行中、失败和已完成任务；
- 完整 Narrator 输出先保存私有快照；
- `output_stored / applying` 重试不再调用 LLM；
- 失败停在具体阶段，支持“从此处重试”或“刷新世界”；
- 应用失败时保留“尚未写入世界”的正文预览；
- 移除覆盖已有正文的笼统读取状态。

### 质量门

- 阶段只前进或同阶段幂等；
- 同一 generationId 只有一个 owner；
- 刷新、断线、租约过期不重复正文；
- 私有快照、租约和原始错误不进入公开 DTO。

## 3. Phase 2：同轮世界动态（已完成）

### 已交付

- Narrator META 增加 `worldActions / activityEntries / importantEventMutation`；
- 每轮仍只有一次 Narrator 请求；
- `WorldActivity` 保存 action、activity 和 event_progress；
- `WorldEvent` 保存战争、阴谋、灾难等持续事件；
- 应用事务逐项过滤普通动态、整项校验事件；
- generation 稳定 ID 保证重放幂等；
- 独立“动态”符文和抽屉；
- activities API、对象跳转、基础未读入口；
- Pantheon / Creator limited / Creator omniscient 可见性投影。

### 质量门

- actor、target、subject、participant 均属于活动现实；
- hidden 不下发 Pantheon 或 Creator limited；
- 动态不能绕过 `immediateChanges` 修改状态；
- 一条非法动态不丢整轮正文；
- 数据库错误时正文与动态整体回滚。

## 4. Phase 3：重要事件关注（已完成）

### 已交付

- `ObserverState.focusedEventId`，旧数据默认 `null`；
- PUT 关注/替换、DELETE 取消，重复请求幂等；
- 一次只能关注活动 Timeline 中一个未解决事件；
- Context Builder 按关注事件、场景相关、最近更新排序；
- 最多注入 3 个事件和 8 条动态；
- 追踪只提高后续权重，不立即调用 LLM、不切场；
- 前端替换确认、取消、未读游标和关注进展提示。

### 质量门

- 模型只能推进上下文明确提供的 event ID；
- Creator omniscient hidden 上下文必须带“世界内尚未知晓”；
- Pantheon 与 Creator limited 不接收 hidden；
- 未读状态不影响知识边界。

## 5. Phase 4：深度整理、现实克隆与存档（明确设计，待完成）

### 4.1 世界整理事件推进

- 合并重复或同源动态；
- 把达到持续性阈值的普通动态升级为重要事件；
- 推进、解决或派生事件；
- 写入带来源消息和时间标签的 event_progress；
- 事件解决后自动清空 `focusedEventId`；
- 维持事件整项原子和稳定 ID，断点重放不重复推进。

### 4.2 现实分叉

- 克隆 `WorldEvent / WorldActivity`；
- 重映射 `parentEventId / originActivityId / eventId`；
- 重映射 participant、actor、target、subject；
- 重映射 source、origin、latest message；
- 重映射 `observerState.focusedEventId`；
- 源现实保持不变，冻结现实不得继续推进事件；
- 发现任何源现实 ID 残留即整体回滚。

### 4.3 存档 v4

- v4 导出完整事件链、动态、关注状态及 hidden 私有内容；
- 不导出任务租约、`outputSnapshot`、内部 error 或 owner 信息；
- v2/v3 导入补空事件、空动态和 `focusedEventId=null`；
- v4 导入预生成 ID 并完整重映射事件图；
- 非法现实树、跨现实引用、悬空关注整体拒绝；
- 旧存档导入后可继续游玩，不补造历史、不调用 LLM。

### 4.4 验收

1. 连续数轮后，同一战争形成可读进展链而非重复新闻；
2. 世界整理可升级、解决和派生事件；
3. 解决当前关注事件后关注自动清空；
4. 分叉后源现实不变，新现实所有事件、动态和关注引用均属于新 Timeline；
5. v4 导出再导入保持事件链和可见性；
6. v2/v3 导入后动态为空但仍可正常生成；
7. Phase 4 不给普通每轮增加额外 Narrator 调用。

## 6. Task 19 文档与发布门

文档同步后执行：

```text
pnpm prisma validate
pnpm prisma generate
pnpm test
pnpm exec tsc --noEmit
pnpm lint
pnpm build
```

集成测试需要 `TEST_DATABASE_URL`。若环境缺失，应记录为环境限制，不得伪报通过。

发布前手工验证：

- opening 在创世动画期间开始并保持幂等；
- 断线后 durable 进度恢复；
- `output_stored` 后模拟应用失败，重试无第二次 LLM；
- Pantheon 看不到 hidden，Creator omniscient 有明确幕后标记；
- 关注替换有确认，关注本身不触发生成；
- 世界整理无章节 UI；
- 标题始终为世界名、纪元和时间。
