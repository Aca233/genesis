# 06 · 里程碑计划

三里程碑递进，每个里程碑结束时都是**可玩版本**。任务粒度到「可独立验收的工作包」；动代码时再细化为具体任务清单。

---

## M1 · 能玩 —— 「一句话创世，开始扮演」

**目标**：从首屏输入到流畅 RP 对话的完整闭环，BYOK 可用，古卷 UI 成形。

### 工作包

| # | 工作包 | 内容 | 验收标准 |
|---|---|---|---|
| 1.1 | 项目骨架 | Next.js + TS + Tailwind + Prisma + Postgres(Docker)；主题 Token（日卷/烛光）；字体接入（文楷/思源宋子集化） | `pnpm dev` 一键起；双模式切换生效 |
| 1.2 | 设置与 BYOK | 双模型槽位 CRUD、AES-256-GCM 加密、三协议适配层（openai-compatible/anthropic/gemini）、连接测试、统一重试 | 三种协议+任一中转站均能通过「试炼一问」 |
| 1.3 | 世界生成 | Genesis prompt + Zod schema + 分批生成；ST 世界书导入解析 | 「40K+凡人修仙传」一句话稳定产出合规卡组，融合公理卡正确出现 |
| 1.4 | 卡片编辑器 | 卡片墙 UI、单卡重掷（带约束）、逐字段手改+player_locked、神谱增删、议程卡封蜡 | 重掷不破坏其他卡一致性；手改字段重掷后保留 |
| 1.5 | 创世演出 | 原初神谕逐字浮现 → 卡组点亮 → 入第一章；可跳过 | 完整播放与跳过均正常 |
| 1.6 | RP 主循环 | Narrator prompt + Context Builder v1（世界卡+近期窗口+世界书关键词触发）+ SSE 流式书页正文 + 玩家金色引文块 + 尺度切换器（三档文体） | 三档文体差异明显；玩家发言零代打 |
| 1.7 | 消息四件套 | 异文（多候选）/朱批/裁去/续笔，悬停手柄 | 四操作均可用且状态一致 |
| 1.8 | 轻状态面板 v1 | 本尊神格页签（位阶/领域/信仰描述）+ 设定集页签（世界卡阅读/手改）；右缘符文列+抽屉框架 | 抽屉五位置占位就绪，两页签可用 |
| 1.9 | 存档 | 多存档列表、手动导出/导入 JSON | 导出→删库→导入完整还原 |

**M1 不含**：章节结算、诸神回合、百科生长、迷雾、编年史（正文即全部记忆，靠上下文窗口）。

## M2 · 有深度 —— 「世界活了起来」

**目标**：章节结算流水线、诸神后台议程、三层记忆、百科全系统、迷雾。这是本作灵魂所在，工期最重的一期。

### 工作包

| # | 工作包 | 内容 | 验收标准 |
|---|---|---|---|
| 2.1 | 章节系统 | 章数据模型、手动翻章、AI 建议翻章（hint 字段）、结算状态机（幂等断点续跑） | 结算中断电/断网后可续跑 |
| 2.2 | 诸神回合 | Pantheon Turn prompt、串行执行器、议程/关系增量更新、隐藏大事记、征兆队列、密约写入、主动事件（下章开场钩子） | 与某神结盟后其后续行动可观测地偏向玩家；征兆在下章正文中无标记出现 |
| 2.3 | 抽取器 | Extractor prompt、分片合并、实体建卡/栏目增量、player_locked 保护、神选者识别、寿数推进、玩家位阶变更 | 一章内新登场人物自动入册；手改栏目不被覆盖 |
| 2.4 | 编年史 | 压缩 prompt、纪年体系（主题卡）、年表页签 UI、实体筛选、揭示补录（「于第N章揭晓」） | 50 章存档年表流畅可读 |
| 2.5 | 百科全量 | 六类面板模板、栏目级迷雾（传闻/残卷样式）、专属编年史、热度分层与复活、程序纹章生成器、标星、上传图 | 每类实体面板完整；dormant 实体再登场自动复活全卡 |
| 2.6 | 正文实体链接 | 服务端 Aho-Corasick 实体名标记、微光链接渲染、悬停快览 | 别名/称号均可命中；长文无性能问题 |
| 2.7 | 检索注入 v2 | 实体索引检索、在场实体强制注入、编年史检索、token 预算分级裁剪、可选 embedding 槽 | 30 章前的神选者再登场时设定不丢（一致性抽查） |
| 2.8 | 查探裁决 | 隐藏大事记检索附入、揭示回填、议程揭示片段进星图神卡 | 占卜可揭开上一章某神密谋并补录年表 |
| 2.9 | 岁月流转演出 | 结算 SSE 进度驱动、低语碎片文案池、失败退出与重试 | 15–60 秒结算体验完整 |
| 2.10 | 星图 | D3-force 手绘天文图、关系线、位阶星等、变化动效、神卡详情 | 关系变化后星图正确重排且有一次性动效 |

## M3 · 完整 —— 「史诗、轮回与生态」

**目标**：陨落/余烬终局、时间线分叉、模板广场、双向 ST 兼容、成书导出。

### 工作包

| # | 工作包 | 内容 | 验收标准 |
|---|---|---|---|
| 3.1 | 位阶与余烬 | 位阶谱系落卡、余烬视角模板变体（文体收窄）、位阶变化微焕 | 跌入余烬后文风明显切换；东山再起恢复 |
| 3.2 | 陨落终章 | 陨灭判定（叙事裁决+玩家确认）、终章生成、已成史只读态、终章演出 | 终章后存档只读且可分叉 |
| 3.3 | 时间线分叉 | 章快照物化、树状 Timeline、年表分叉入口、分叉管理 UI | 从第 N 章分叉后两线独立推进互不污染 |
| 3.4 | 《创世史》导出 | 章题+定稿正文+小结拼装、Markdown 直出、EPUB 打包、书封（程序纹章） | 百章存档导出 EPUB 可在阅读器正常阅读 |
| 3.5 | ST 双向兼容 | 导出：导入条目还原 + 世界卡/百科编译为 entries；格式往返测试 | ST 导入本作导出的世界书可正常触发 |
| 3.6 | 模板广场 | 模板发布（卡组+世界书，不含正文）、浏览/一键开局、自评标签、moderation_state 预留 | 他人模板一键开出可玩新局 |
| 3.7 | VPS 部署 | docker-compose.prod（app+postgres+caddy）、basic-auth、部署文档 | 一条命令在 VPS 起全套并 HTTPS 访问 |

## 里程碑外（预留不做）

Discord OAuth 多用户、公开运营审核体系、AI 生图接入（image_url 字段已预留）、用量面板（llm_calls 已记录）、移动端专项交互优化。

## 风险与对策

| 风险 | 对策 |
|---|---|
| 玩家所用模型结构化输出能力弱 → 卡组/抽取失败 | Zod 校验+携错重问×2；分批生成降低单次复杂度；失败降级（诸神「静观」/待重抽标记） |
| 中转站兼容性千奇百怪 | 协议适配层只依赖最小公共 API 面；llm_calls 日志辅助玩家自查；连接测试前置 |
| 长局一致性漂移 | 三层记忆+player_locked+融合公理恒注入；验收含 30 章一致性抽查 |
| 结算 15–60 秒中断 | 状态机幂等断点续跑（2.1 即内建，不留到后期） |
| 抽取器误建卡污染百科 | 建卡阈值（「值得入册」判据写入 prompt）+ 玩家可删卡/合并（M2.5 含基础管理） |
