# 06 · 前端设计

## 1. 连续世界界面

游戏内没有玩家可见章节。`Chapter` 只作为后端检查点，正文区连续展平最近记录，不显示章号、章题、章节边界或“结束本章”按钮。

页面标题固定为：

```text
世界名 · 纪元 · 时间
```

纪元来自 `RealityState.currentEra`，时间来自 `ObserverState.timeLabel`。时之仪位于输入区，负责选择下一轮默认时间跨度。

两种模式共用：

- 一个正文流；
- 一个 textarea；
- 时之仪；
- “续写 / 发送 / 搁笔”；
- 真实任务状态条。

Creator 不再显示“观测/改写”切换，意图统一交给 Narrator。

## 2. 开局正文

点击创世后，世界物化、就绪动画与 opening 生成并行：

1. 原初神谕沉入纸面；
2. 世界卡与符文逐步点亮；
3. opening 在后台立即开始流式生成；
4. 动画结束时，正文应已部分或大部分可读；
5. 跳过动画只跳过视觉，不启动第二份 opening。

Opening 与普通正文共用幂等 generation 机制，刷新或断线后恢复同一任务。

## 3. 真实任务状态条

状态条贴近输入区，不覆盖已有正文。三类任务均由真实后端阶段驱动：

### 正文

```text
接收请求 → 组装上下文 → 生成正文
→ 校验并保存模型输出 → 写入正文与状态 → 更新世界动态
```

### 世界整理

```text
读取检查点 → 推演诸神行动 → 抽取持久变化
→ 更新编年史 → 生成内部快照 → 完成
```

### 现实分叉

```text
理解追溯意图 → 建立计划 → 克隆现实
→ 应用新历史 → 生成结果正文 → 整理并切换
```

视觉状态：

- pending：灰色空心；
- running：烫金高亮；
- completed：淡金勾；
- failed：朱红并停在具体步骤。

可恢复失败显示“从此处重试”；世界已变化等不可恢复错误只显示“刷新世界”。完整正文已生成但尚未应用时，预览继续可读并标“尚未写入世界”，输入暂时锁定。禁止用笼统“读取中”遮挡正文。

## 4. 独立「动态」抽屉

右缘符文新增独立“动态”入口；移动端进入底部栏。面板分三段：

1. **当前关注**：标题、阶段、摘要、最近进展、参与者、可见性与取消关注；
2. **重要事件**：未解决优先，按最近更新排列；当前关注置顶；展开后按时间展示进展链；
3. **近期动态**：按时间倒序分页，展示纪元、时间、类型、正文和相关对象。

动态中的神、人物、势力、地点等可跳转对应详情抽屉。打开面板不触发聊天、不推进时间、不调用 LLM。

## 5. 关注交互

- 一次只能关注一个重要事件；
- 无关注时，事件卡显示“追踪”；
- 已有关注时追踪另一项，前端先确认“替换当前关注”；
- 当前事件显示“取消追踪”；
- 请求成功后只更新本地活动视图与观察状态；
- 关注不会立即生成正文或切换当前场景。

事件解决后，服务端清空关注；前端刷新时移除当前关注卡。

## 6. 未读状态

- 动态符文显示本地未读数量；
- 重要事件进入新阶段时短暂烫金；
- 关注事件出现进展时显示更醒目的圆点；
- 打开动态抽屉后，把当前最新活动游标记为已读。

未读游标是纯 UI 状态，不写入 LLM 上下文，不改变 `public / player_known / hidden`。

## 7. 可见性呈现

| 模式 | public | player_known | hidden |
|---|---|---|---|
| Pantheon | 正常显示 | 正常显示 | 不下发浏览器 |
| Creator limited | 正常显示 | 正常显示 | 不下发浏览器 |
| Creator omniscient | “世人皆知” | “局部知晓” | “天外批注 · 世界内尚未知晓” |

hidden 必须由服务端过滤，前端不能靠折叠或 CSS 保密。Creator 看见幕后内容不会改变 NPC 认知。

## 8. 自动世界整理

整理时正文保留原位，输入区锁定并显示当前真实步骤；不出现翻页、章末对话或“结束本章”仪式。完成后静默刷新：

- 纪元和时间；
- 正文编辑边界；
- 实体索引；
- 动态、事件与关注状态。

失败时保留正文和已完成步骤，显示“继续整理世界”。

## 9. Phase 4 前端接入

Phase 4 不新增主循环入口，只扩展现有动态面板：

- 展示整理合并后的单一动态；
- 支持普通动态升级为重要事件后的来源链接；
- 已解决事件折叠到历史区；
- 派生事件显示父子关系；
- 现实切换后重新读取新 Timeline 的动态和关注 ID；
- v4 存档导入后按新 ID 恢复事件链，未读游标按本地规则重新计算。
