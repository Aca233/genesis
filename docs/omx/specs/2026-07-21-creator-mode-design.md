# 「诸神共世 / 创世主」双模式设计

**日期：** 2026-07-21  
**状态：** 已通过对话评审，待书面规格复核

## 1. 目标

在保留当前玩法为「诸神共世」的同时，增加独立的「创世主」模式。

- **诸神共世（`pantheon`）**：玩家是神谱中的一员，拥有玩家神卡、位阶与神权，受世界法则、能力边界和迷雾约束。
- **创世主（`creator`）**：玩家位于世界之外，不是世界实体；世界继续自主运转，玩家默认全知，并可通过独立的「改写现实」通道绝对改变规则、历史、人物、诸神与因果。

世界模式在创建时确定，存档内不可切换。旧存档一律兼容为 `pantheon`。

## 2. 设计原则

1. **真实建模**：创世主模式不创建隐藏的无限玩家神，也不生成玩家神卡。
2. **模式隔离**：创世、视角和交互在明确策略边界分流，避免创世主规则污染诸神共世。
3. **共享活世界**：诸神、人物、势力、百科、章节与自主演化继续共享现有模型和运行系统。
4. **绝对但可恢复**：现实敕令不得失败于力量或设定冲突；每次改写前自动分支，旧现实永不被破坏。
5. **最小充分改变**：敕令没有指定的部分只做满足意图所必需的调整。
6. **模型规划、服务端执行**：LLM 产出结构化改写计划，服务端校验并以确定性补丁执行，不允许模型直接任意写库。

## 3. 模式与数据架构

### 3.1 世界模式

新增稳定类型：

```ts
type WorldMode = "pantheon" | "creator";
```

在以下位置持久化模式：

- `World.mode`：默认 `pantheon`，创建后无修改 API。
- `GenesisTask.mode`：任务创建时冻结，确保恢复、重试和租约接管不串用规则。
- 导出存档中的 `world.mode`。

### 3.2 模式化创世卡组

世界卡组改为判别联合：

```ts
type WorldDeck =
  | {
      mode: "pantheon";
      playerGod: PlayerGodCard;
      majorGods: PantheonMajorGodCard[];
      // 公共世界卡
    }
  | {
      mode: "creator";
      majorGods: CreatorMajorGodCard[];
      // 公共世界卡；不存在 playerGod
    };
```

约束：

- `pantheon` 必须且只能物化一位 `isPlayer = true` 的神。
- `creator` 的卡组不得含 `playerGod`，运行态不得存在玩家神。
- 创世主模式主神议程不含「对玩家神态度」，只记录自身目标、手段、密谋及与世界内对象的关系。
- 玩家神素材只可用于 `pantheon`；普通神明、世界、人物等素材两种模式均可用。

### 3.3 分支级现实状态

创世主的平行现实可能拥有不同法则，因此主题、文风、宇宙论等不能只以 `World` 级字段作为运行时真相。新增：

```ts
type RealityState = {
  theme: ThemeCard;
  style: StyleCard;
  cosmology: CosmologyCard;
  fusionAxiom: FusionAxiomCard | null;
  currentEra: string;
  establishedFacts: EstablishedFact[];
};
```

- `Timeline.realityState` 保存该分支的现实状态。
- 根时间线从最终创世卡组初始化。
- 新现实分支完整继承源分支的 `realityState`，随后应用补丁。
- 叙事、诸神回合、百科抽取和现实改写均读取当前时间线状态。
- `World` 旧卡片字段暂留作兼容；旧存档无 `realityState` 时以它们作为回退源。

### 3.4 三个策略边界

1. **Genesis Policy**：选择卡组契约、创世 Prompt 与开局物化约束。
2. **Perspective Policy**：选择叙事身份、上下文投影和信息可见性。
3. **Interaction Policy**：选择可用输入通道与对应执行流水线。

共享模块不自行猜测模式，模式差异由上述策略传入。

## 4. 创世入口

首页在原初神谕输入框上方提供两个模式卡：

### 4.1 诸神共世

> 作为神谱中的一员降临，与诸神争斗、结盟，在世界法则之内书写神话。

- 保持现有流程和提示词语义。
- 原初神谕描述玩家是谁以及世界是什么样。
- 生成玩家神卡、神权、位阶及其他主神。

### 4.2 创世主

> 立于世界之外，观看一个自行运转的宇宙，并以绝对敕令改写现实。

- 原初神谕只需描述要创造的世界。
- 生成世界内诸神、种族、人物、势力和时代冲突。
- 不生成玩家身份、玩家神卡、玩家神权或玩家位阶。
- 模式随 `GenesisTask` 保存；进度页恢复时使用任务模式。

## 5. 创世主视角与界面

### 5.1 天外视界

创世主模式移除「本尊神格」，增加「天外视界」：

- 当前现实分支；
- 当前观察时间与地点；
- 当前观察视角；
- 活跃化身；
- 最近现实改写；
- 「迷雾观测」体验开关。

神谱只展示世界内诸神。隐藏议程、幕后行动和未公开真相以「天外批注」样式展示，明确区分创世主知识与世界内角色知识。

### 5.2 全知与迷雾观测

- 创世主默认绕过玩家可见性投影，可读取完整议程、隐藏能力、幕后编年史、真实历史及所有现实分支。
- 数据原有 `known / rumored / hidden`、`revealed` 等标记保持不变。
- 开启「迷雾观测」后复用受限投影，只改变界面所见，不改变世界内认知或数据可见性。
- 敕令记录、旧现实和版本树始终对创世主可见。

### 5.3 观察状态

```ts
type ObserverState = {
  focusType: "world" | "place" | "entity" | "god" | "avatar";
  focusId?: string;
  timeLabel: string;
  viewpoint: "omniscient" | "limited";
};
```

该状态只控制下一段叙事焦点，不形成创世主实体，也不限制权限。

## 6. 两种输入通道

### 6.1 观察世界

用于观察、询问、聚焦和推进时间，例如：

- 看看北境现在发生了什么；
- 将时间推进一百年；
- 跟随这名流浪者；
- 描写诸神会议的全过程；
- 为什么太阳神正在背叛月神？

普通观察可以触发世界推进与自主结算，但不会把玩家措辞自动当作最高事实，也不会创建现实分支。

### 6.2 改写现实

独立按钮切换到醒目的「现实敕令」输入状态，例如：

- 从现在起，所有魔法都必须付出记忆作为代价；
- 这个王朝从未存在过；
- 让死者伊澜在三日后归来，并保留全部记忆；
- 令两颗月亮自世界诞生时便悬于天空。

敕令不进行成功率、神力、位阶、资源或距离判定。世界法则如与敕令冲突，敕令成为更高层事实。诸神可以反应、恐惧或反抗其后果，但不能阻止敕令声明的事实成立。

不设置提交后二次确认；自动现实分支承担误操作恢复能力。

## 7. 可选化身

创世主默认无身体，但可创建一个或多个世界内化身：

- 化身作为普通 `character` 实体存在，可拥有种族、外貌、身份、能力和关系。
- 化身遵守创世主为其指定的世界内规则，可受伤、被封印或死亡。
- 化身遭遇不影响创世主本体。
- 创世主可进入、退出、收回或重塑化身。
- 同一叙事焦点默认只跟随一个活跃化身。
- 世界内角色只知道化身显露的信息，除非敕令公开其本质。
- 进入化身仅改变「观察世界」的叙事视角，不削弱「改写现实」权限。

首版不创建独立的创世主身份表；化身身份和当前焦点由实体及观察状态表达。

## 8. 绝对改写流水线

### 8.1 改写记录

新增 `RealityRewrite`：

```ts
type RealityRewrite = {
  id: string;
  sourceTimelineId: string;
  resultTimelineId: string | null;
  sourceChapterId: string;
  decree: string;
  scope: "prospective" | "retroactive" | "memory_only";
  status: "planning" | "applying" | "narrating" | "completed" | "failed";
  plan: RewritePlan | null;
  summary: string | null;
  idempotencyKey: string;
  leaseToken: string | null;
  leaseExpiresAt: Date | null;
  error: string | null;
  createdAt: Date;
  updatedAt: Date;
};
```

### 8.2 结构化计划

```ts
type RewritePlan = {
  scope: "prospective" | "retroactive" | "memory_only";
  interpretation: string;
  effectivePoint: string;
  branchName: string;
  worldPatches: WorldPatch[];
  entityPatches: EntityPatch[];
  historyPatches: HistoryPatch[];
  memoryPatches: MemoryPatch[];
  causalConsequences: Consequence[];
  narrationFocus: string;
};
```

补丁类型使用白名单操作和稳定引用；执行器拒绝未知路径、跨世界引用、模式违规和破坏所有权约束的计划。

### 8.3 执行顺序

1. 以世界级互斥锁/租约确认当前无叙事、结算或改写任务。
2. 记录原始敕令并生成结构化计划；此时不改动现实。
3. 校验计划语义、补丁白名单和引用。
4. 在单个数据库事务中：
   - 验证源时间线仍为当前现实；
   - 克隆源时间线为子分支；
   - 复制分支级现实状态及所有运行态数据；
   - 按固定顺序应用补丁；
   - 执行 Zod、跨引用、所有权和模式校验；
   - 将新分支设为 `activeTimelineId`；
   - 把改写状态推进至 `narrating`。
5. 在新分支生成「现实重铸结果」叙事。
6. 标记 `completed`。

若步骤 4 之前失败，不创建分支；若事务失败，当前现实保持不变。若事务成功而结果叙事失败，新分支仍是有效现实，任务可幂等补写叙事。

### 8.4 语义范围

- `prospective`：含「从现在起」「此刻以后」「三日后」等，或语义不明确时的默认值。
- `retroactive`：含「自古以来」「从未存在」「改写历史」等。
- `memory_only`：明确要求忘记、误认或更改记录，但未要求客观事件变化。

一条敕令可有多个子命令。每个子命令保留自己的生效点；顶层 `scope` 取影响最深的一档，用于索引和展示。

### 8.5 从当前生效

- 保留旧章节、历史与记忆。
- 在生效点新增创世主改写编年史节点。
- 更新当前状态及后续叙事上下文。
- 世界内对象可察觉变化，除非敕令要求无感过渡。

### 8.6 追溯历史

新现实重构受影响的：

- 编年史和当前时代状态；
- 人物出生、死亡、关系与能力；
- 神明议程、关系与信仰；
- 势力兴衰和百科；
- 众生记忆与因果结果。

既有消息不被伪造性覆盖，而在新分支标记为「前现实文本」；系统生成新历史摘要和一致的当前态。新现实内的角色默认认为改写后的历史一直成立，旧历史只在创世主全知层可见。

### 8.7 仅记忆改写

- 客观历史与真实编年史不变。
- 更新人物认知、公开记录、传说及受限视角百科。
- 创世主仍可见真实历史。
- 证据可能与错误记忆冲突，除非敕令同时要求证据被改写。

### 8.8 应用顺序

结构补丁严格按以下顺序处理：

1. 时间线现实状态；
2. 神明与关系；
3. 实体与百科栏目；
4. 能力与世界规则；
5. 编年史与记忆层；
6. 诸神议程；
7. 待发生事件与征兆；
8. 当前观察状态；
9. 结果叙事。

### 8.9 结果呈现

完成后显示「天外敕令」卡：

- 原始敕令；
- 系统解释；
- 判定范围与生效点；
- 主要变化；
- 新现实名称；
- 返回前现实入口。

语义解析失败时不创建分支，保留输入并返回可修改的解释错误。

## 9. 现实版本树

### 9.1 时间线元数据

扩展 `Timeline`：

```ts
Timeline {
  parentId: string | null;
  forkChapter: number | null;
  forkRewriteId: string | null;
  branchName: string;
  branchSummary: string | null;
  realityState: Json;
}
```

- 根节点名默认为「原初现实」。
- 每次现实改写生成当前分支的一个子节点。
- 父子必须属于同一世界，图结构不得有环。
- 同名分支允许存在，以内部 ID 区分。
- 非当前分支冻结，不执行叙事、诸神回合或后台演化。

### 9.2 撤销与切换

「撤销最近改写」等价于把 `World.activeTimelineId` 指回父分支：

- 子分支不会删除；
- 父分支立即成为当前现实；
- 从父分支再次改写将产生平行子分支。

切换任意旧分支后，该分支立即成为当前现实，后续观察、叙事和改写均发生在那里。切换使用条件更新，确保提交时预期的旧 `activeTimelineId` 仍成立，避免多标签页相互覆盖。

世界存在进行中的叙事、结算或改写任务时禁止切换。

### 9.3 现实树界面

右侧增加「现实树」入口，节点显示：

- 名称与一句摘要；
- 来源章节和敕令；
- 当前现实标记；
- 最后活动时间；
- 子分支数量；
- 进入、查看敕令、重命名操作。

分支名由模型根据敕令生成 4–10 个字，玩家可重命名；名称不进入世界内叙事。

### 9.4 删除规则

- 根现实不可删除。
- 当前现实不可删除。
- 删除有子节点的非当前分支时，删除整棵子树并明确展示影响范围。
- 首版不支持分支合并。

## 10. 世界自主运转与章节

- 创世主模式保留诸神回合、隐藏议程、势力演化和人物行动。
- 「观察世界」可追加叙事、推进时间并触发正常章末结算。
- 每次现实改写都会创建新分支，并在新分支开启一个章节节点；首条内容为改写结果叙事。
- 创世主可见诸神回合的隐藏结果，但世界内对象仍只依据自身知识行动。
- 自主演化结果永远不是对现实敕令的限制。

## 11. 并发、幂等与恢复

- 每个世界同时最多运行一个普通生成、章末结算或现实改写任务。
- 改写任务使用幂等键、租约和状态机，刷新页面后可恢复进度。
- 服务重启后：
  - 未应用计划可重新取得租约后执行；
  - 已提交事务但未生成结果叙事的任务只补叙事；
  - 半成品分支不会成为当前现实。
- `resultTimelineId` 唯一绑定一次改写，重试不得重复克隆。
- 非当前分支的生成请求在写入前再次校验活动时间线，避免切换后的迟到响应污染现实。

## 12. 导入、导出与兼容

导出格式升级，包含：

- `World.mode`；
- 完整现实树；
- 每条时间线的 `realityState`、分支元数据与观察状态；
- 全部 `RealityRewrite` 记录。

导入时重新映射所有 ID，并验证：

- 父子时间线属于同一世界；
- 根节点唯一；
- 图结构无环；
- `activeTimelineId` 存在；
- 改写的源/结果分支存在且关系一致；
- `creator` 世界无玩家神；
- `pantheon` 世界每条有效运行时间线恰有一位玩家神。

旧版存档：

- 无 `mode` 时补为 `pantheon`；
- 无 `realityState` 时从世界级卡片构造；
- 无分支名时根节点补为「原初现实」，其他节点按旧分叉信息生成兼容名称。

## 13. 测试与验收

### 13.1 单元测试

- 模式 Schema、旧世界默认迁移和模式不可变约束。
- 两种创世卡组的判别联合校验。
- `creator` 拒绝 `playerGod`；`pantheon` 必须且只能有一位玩家神。
- 敕令范围识别和语义不明时默认 `prospective`。
- 补丁白名单、引用、所有权和模式规则验证。
- 现实树无环、同世界父子和活动节点切换规则。
- 全知与迷雾观测两套投影。

### 13.2 集成测试

- 两种模式从任务创建、生成、恢复到开局。
- 创世主世界物化后不存在玩家神。
- 普通观察追加叙事但不创建分支。
- 改写成功后源分支不变，新分支成为当前现实。
- 改写失败不产生半成品活动分支。
- 事务后叙事失败可幂等补写且不重复分支。
- 撤销后返回父现实，再改写形成平行分支。
- 追溯改写同步历史、百科、关系和现实状态。
- 记忆改写不改变真实编年史。
- 非当前分支不执行诸神回合，迟到生成结果不污染当前现实。
- 导出再导入后模式、现实树和改写记录一致。

### 13.3 浏览器验收

- 首页模式选择清晰，文案和输入占位随模式变化。
- 两种模式的创世结果符合各自契约。
- 创世主界面无「本尊神格」，有「天外视界」和「现实树」。
- 「观察世界 / 改写现实」视觉状态明确。
- 改写完成后显示解释、影响摘要、分支名和返回入口。
- 现实树支持浏览、切换、撤销、重命名和从旧节点分叉。
- 全知显示隐藏议程；迷雾观测正确过滤且不修改数据。
- 移动端可完成模式选择、现实改写和分支切换。

## 14. 首版范围

### 包含

- 双模式创世与不可变模式；
- 创世主无玩家神；
- 世界外默认全知观察；
- 可选化身；
- 独立绝对改写通道；
- 当前生效、追溯历史、仅记忆三类语义；
- 改写前自动分支；
- 撤销、切换、重命名及现实树；
- 世界自主运转；
- 导入导出兼容；
- 自动化测试和浏览器验收。

### 不包含
