# 创世流式真实进度设计

## 目标

创世请求不再让首页等待一个不可观察的长响应。系统先创建持久化任务并立即进入全屏进度页，通过流式扫描模型 JSON 输出展示真实阶段；数据库是刷新、断网和重连后的进度真相源。

## 流程

1. 首页向 `POST /api/genesis/tasks` 提交神谕与可选世界书。
2. 服务端验证输入，创建 `queued` 任务并返回 `202 + taskId`。
3. 浏览器跳转 `/genesis/progress/[taskId]`，读取任务快照并建立 SSE。
4. SSE/状态查询触发 runner。runner 用数据库条件更新和租约防止重复执行。
5. runner 调用 LLM 流式接口；状态机扫描 JSON 顶层键，仅在值完整闭合后记录字段完成。
6. 每个模型文本块续租；约每秒持久化原始检查点，阶段变更立即持久化。
7. 流结束后执行 `WorldDeckSchema` 和 `validateDeckReferences`。校验失败进入修补阶段，定向生成完整修复卡组并再次执行两项权威校验。
8. 事务内创建世界草稿并将任务标记为完成；进度页收到完成事件后跳转卡组编辑器。
9. 失败记录具体阶段和安全错误摘要，用户可重置同一任务重试。

## 阶段

- `oracle` 聆听神谕
- `laws` 奠定世界法则
- `gods` 铸造诸神
- `peoples` 铺展众生与疆域
- `characters` 编织命运人物
- `conflict` 确立时代冲突
- `validation` 校验世界引用
- `repair` 修补命运裂隙
- `saving` 世界凝固成形
- `completed` 创世完成

## 正确性边界

- 不使用定时器伪造百分比或阶段。
- 扫描器处理任意 chunk 边界、嵌套对象/数组、字符串和转义。
- Prompt 固定顶层字段顺序，但阶段判定依赖字段集合，不依赖到达次序。
- 增量扫描只负责可观察进度，最终 Zod Schema 与引用校验才决定成功。
- 进度只合并不删除；修复不会倒退已展示阶段。
- 原始模型输出只存服务端，不通过任务 DTO 或 SSE 暴露。
- 世界仅在完整校验成功后创建，且任务完成与世界创建位于同一事务。
