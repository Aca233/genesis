# 《创世》结构化能力系统设计

- 日期：2026-07-20
- 状态：已完成对话评审，待书面规格复核
- 范围：种族能力、玩家神/主神技能、主要人物与技能、叙事注入、迷雾、章末演化、界面、存档兼容

## 1. 背景与目标

当前世界卡组中的种族只有特质、寿命、分布与诸神渊源；神明只有领域、位阶等概念；势力关键人物只是姓名；后续人物实体也没有可可靠继承、揭示与演化的结构化技能。叙事模型因而无法稳定判断角色会什么、何时能用、有什么代价和边界。

本期建立独立的结构化能力模型，目标如下：

1. 为种族提供可执行的先天能力和族群技艺。
2. 为玩家神、主神、开局主要人物及后续晋升的主要人物提供技能。
3. 让凡人正确继承种族先天能力，只在明确掌握后获得族群技艺。
4. 支持能力的隐藏、传闻、揭示、觉醒、成长、受损、封印和失去。
5. 将角色当前实际可用能力可靠地注入叙事与诸神后台回合。
6. 保持系统叙事化，不引入数值战斗与技能按钮。

## 2. 已确认的产品决定

- 采用独立的结构化能力模型，不把能力仅作为普通文字栏目或现有 JSON 卡片附属字段。
- 创世阶段生成 6–12 位统一的主要人物；势力关键人物引用这份名录。
- 玩家神、主神、开局主要人物及后续晋升的主要人物都有结构化技能。
- 能力会随有明确依据的剧情演化。
- 玩家神技能全部可见；种族公开能力默认可见；其他神和人物的底牌、禁术与未觉醒能力分层揭示。
- 种族能力分为默认继承的“先天能力”和必须明确学习的“族群技艺”。
- 旧世界不迁移、不回填、不提供一键补全；只在后续剧情明确展现能力时渐进建档。
- 章节流程保持现状：同一章可多轮对话，玩家点击“结束本章”后集中结算。
- 时之仪继续影响每次回复；能力抽取需要读取各条消息的尺度证据，而不能只依赖整章众数尺度。

## 3. 非目标

本期不做以下内容：

- 不改变章节与回合流程，不自动翻章。
- 不增加技能快捷栏或点击发动按钮。
- 不增加法力值、伤害、冷却、成功率等数值系统。
- 不为旧世界自动生成能力谱或主要人物名录。
- 不为每个普通路人生成完整技能卡。
- 不实现复杂混血比例或遗传模拟。
- 不让 AI 在缺少正文依据时自动补齐角色技能。
- 不扩展为职业、装备、天赋树或角色等级系统。

## 4. 领域模型

### 4.1 主要人物与关系

继续使用现有 `Entity(type = "character")` 表示人物，并增加：

- `isMajorCharacter: Boolean`：是否为主要人物；普通人物可随剧情晋升。
- `raceId: String?`：关联主要种族实体；旧人物及无法归类者可为空。
- `EntityMembership`：人物与势力之间的多对多关系，至少包含人物、势力、职务和是否主要归属。

势力的关键人物由关系数据解析，不再以不可跳转的纯姓名作为运行时真相。同一人物可关联多个势力，也可没有势力归属。

### 4.2 Ability

种族、人物和神明共用统一的 `Ability` 模型。建议字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 数据库标识 |
| `timelineId` | 所属时间线，用于隔离与权限校验 |
| `entityId` | 可选；种族或人物实体所有者 |
| `godId` | 可选；玩家神、主神或次要神所有者 |
| `sourceAbilityId` | 可选；继承、掌握或覆写所源自的种族能力 |
| `name` | 能力名 |
| `kind` | `racial_innate` / `racial_tradition` / `personal` / `divine` |
| `effect` | 叙事中的实际效果 |
| `trigger` | 被动生效或主动发动条件 |
| `cost` | 代价；没有时明确为“无” |
| `limitations` | 边界、克制方式及不能做到的事 |
| `mastery` | `unawakened` / `novice` / `adept` / `expert` / `master` |
| `state` | `normal` / `enhanced` / `impaired` / `sealed` / `lost` / `deprecated` |
| `visibility` | `known` / `rumored` / `hidden` |
| `rumorText` | 传闻态下可展示的模糊描述 |
| `lockedFields` | 玩家锁定、AI 不得改写的字段路径 |
| `version` | 乐观并发版本号 |
| `createdAt` / `updatedAt` | 审计时间 |

约束：

1. `entityId` 与 `godId` 必须恰有一个非空。
2. 所有者与能力必须属于同一时间线。
3. 种族模板能力使用 `racial_innate` 或 `racial_tradition`，直接所有者必须是 `race` 实体，且 `sourceAbilityId` 为空。
4. 人物对先天能力的个体覆写仍使用 `racial_innate`，人物对族群技艺的掌握记录仍使用 `racial_tradition`；这两类派生记录的直接所有者必须是 `character` 实体，且 `sourceAbilityId` 必须指向同类型的种族模板能力。
5. `personal` 的直接所有者必须是 `character` 实体，且 `sourceAbilityId` 为空。
6. `divine` 的直接所有者必须是神明，且 `sourceAbilityId` 为空。
7. `sourceAbilityId` 与派生能力必须处于同一时间线；来源所有者必须是 `race` 实体。
8. 来源引用不能形成环。

数据库不易表达的跨表所有者约束由能力服务层和事务入口强制执行，并通过测试覆盖。

### 4.3 AbilityEvent

每次剧情造成能力变化时记录不可变事件：

| 字段 | 说明 |
| --- | --- |
| `id` | 事件标识 |
| `abilityId` | 被改变的能力 |
| `chapterId` | 变化发生的章节 |
| `messageId` | 可选；最直接的正文证据 |
| `type` | `awakened` / `learned` / `improved` / `mutated` / `impaired` / `sealed` / `restored` / `lost` / `revealed` / `deprecated` |
| `before` / `after` | 变化前后的相关状态快照 |
| `evidence` | 明确的剧情依据摘录或描述 |
| `scale` | 证据消息对应的时之仪档位 |
| `dedupeKey` | 断点续跑时的幂等键 |
| `createdAt` | 记录时间 |

`dedupeKey` 唯一。能力不会因失去而物理删除；状态及事件历史保留其沿革。

## 5. 种族继承语义

能力解析采用“默认继承 + 个体覆写”，避免为每个角色复制整套种族能力。

1. 种族的 `racial_innate` 默认对所有该种族人物生效。
2. 种族的 `racial_tradition` 不自动生效。
3. 人物明确掌握族群技艺时，创建一条人物能力记录，`sourceAbilityId` 指向该技艺。
4. 人物对先天能力的缺失、强化、变异、受损或封印，也创建一条来源覆写记录。
5. 没有个体覆写时，人物读取种族能力的当前版本。
6. 混血或特殊血脉保留一个主要 `raceId`，其他血脉效果用有来源的个体能力补充，不建立遗传比例系统。
7. 同一人物对同一来源能力只能有一条有效覆写/掌握记录。

示例：夜裔的“夜视”为先天能力，普通夜裔不保存副本；失去视觉的人物保存来源为“夜视”、状态为 `lost` 的覆写。族群秘术“影行”只有人物明确习得后才保存其掌握记录。

## 6. 创世卡组扩展

### 6.1 稳定引用

草稿卡组中的种族、势力、主要人物和能力都具有同类内唯一的稳定 `ref`：

- 人物的 `raceRef` 指向种族。
- 人物的 `factionMemberships[].factionRef` 指向势力。
- 势力的 `keyCharacterRefs` 指向主要人物。
- 人物掌握的族群技艺及先天能力覆写指向种族能力 `ref`。

显示名称不是关系主键，因此重命名不会破坏引用。删除被引用条目时，编辑器必须列出影响并要求先解绑或确认级联清理。

### 6.2 种族卡

每个种族通常生成 2–5 项能力，仅允许：

- `racial_innate`：先天能力；族人默认继承。
- `racial_tradition`：族群技艺；需要学习或传承。

公开能力默认 `known`。只有设定确有秘密血脉或失传传承时，才使用 `rumored` 或 `hidden`。

### 6.3 玩家神与主神

- 玩家神生成 3–6 项 `divine` 技能，全部对玩家可见。
- 每位主神生成 3–6 项 `divine` 技能，至少一项为已知，可包含隐藏底牌、禁术或未觉醒能力。
- 技能由领域、位阶、信仰、人格、议程、世界力量体系及原初神谕约束。
- 隐藏神权不进入玩家可见卡片或普通行动建议。

### 6.4 主要人物

新增统一的 `majorCharacters` 数组，创世时生成 6–12 位。每位包含：

- `ref`、姓名、别名、身份和年龄阶段；
- `raceRef`；
- 势力归属及职务；
- 性格、目标和当前处境；
- 与诸神、时代冲突的关系；
- 已掌握的族群技艺引用；
- 先天能力的缺失、强化或变异覆写；
- 2–5 项个人技能及其可见性和初始状态。

主要人物不等于战斗角色。祭司、谋士、工匠、学者、统治者和先知可以拥有仪式、政治、知识、工艺、统御或调查技能。

### 6.5 生成质量规则

- 已有 IP 存在正式能力时优先采用原设。
- 每项能力必须明确效果、触发、代价与限制。
- 不生成同义重复技能。
- 角色能力不得越过世界力量体系与角色位阶。
- 隐藏能力必须服务于人物秘密、时代暗流或诸神议程。
- 人物不得掌握卡片中未引用的族群技艺。
- 普通先天能力不重复写入人物卡，只记录例外。

后端进行跨卡引用校验；无效引用、错误来源或重复人物触发一次定向修复。修复仍失败时保留草稿并给出可读错误，不允许开局。

## 7. 创世编辑与开局物化

创世页增加：

- 种族能力编辑、增删与字段锁定；
- 玩家神完整神权技能；
- 主神已知技能及“封蜡天机”隐藏项；
- 6–12 张主要人物卡；
- 势力关键人物引用选择器；
- 人物的继承摘要、族群技艺、先天例外和个人技能。

重掷卡片时保留稳定引用和玩家锁定字段。

开局在一个数据库事务中完成：

1. 创建种族和势力实体。
2. 创建主要人物实体。
3. 建立人物—种族和人物—势力关系。
4. 创建种族能力。
5. 创建玩家神、主神及其神权技能。
6. 创建人物个人技能、族群技艺掌握记录和先天能力覆写。
7. 再次校验运行时引用。
8. 创建第一章并切换世界状态。

任一步骤失败均整体回滚。

## 8. 当前实际能力解析

`ability-resolver` 为人物或神明计算当前实际能力，作为唯一真相来源：

- 合并种族当前正常先天能力；
- 应用人物针对来源能力的覆写；
- 加入明确掌握的族群技艺；
- 加入个人技能或神权技能；
- `unawakened`、`sealed`、`lost`、`deprecated` 不进入正常可用集合；
- `impaired` 保留但携带受损限制；
- 掌握程度影响叙事表现，不转换为固定数值。

前端和 Prompt 不能各自实现合并逻辑。

## 9. 叙事上下文与裁决

### 9.1 玩家可知层

包含：

- 玩家神自己的全部技能；
- 当前相关种族的公开能力；
- 人物和神明已揭示技能；
- 传闻技能的 `rumorText`。

行动建议只能引用这一层的信息。

### 9.2 幕后作者层

仅当能力拥有者在当前场景、正在被调查，或触发条件与剧情相关时，选择性注入隐藏能力。模型指令必须说明：

- 这是作者侧秘密；
- 条件未满足时不得点明；
- 可根据拥有者目标决定是否发动；
- 被清楚见证后必须返回揭示信号。

诸神后台回合可读取该神自身的完整有效技能，但公开征兆不得直接泄露秘密。

### 9.3 叙事裁决

史官依次考虑：

1. 能力效果和边界；
2. 当前状态与掌握程度；
3. 触发条件；
4. 代价是否可支付；
5. 对手能力、神力位阶与世界法则；
6. 当前时之仪尺度；
7. 已建立的场景事实。

能力不是必胜按钮。叙事不得临时扩大能力边界。

### 9.4 时之仪

- 一瞬／一幕：强调即时发动、反应、仪式步骤和具体代价。
- 数年／数十年：可表现修习、传承扩散、衰退及长期工程。
- 百年：可表现流派形成、失传、变异及族群历史影响。

章末能力抽取必须关联具体证据消息及其 `scale`。整章主尺度仅可作为辅助背景，不能替代逐消息证据。

## 10. 迷雾与揭示

隐藏或传闻技能可由以下事件揭示：

- 在玩家面前明确发动；
- 合理的占卜、调查、审问或知识手段确认；
- 拥有者主动告知；
- 可靠史料或剧情证据证实。

叙事 META 返回能力揭示信号。服务端校验能力属于当前时间线，并根据证据决定：

- 异常现象但原理未明：`hidden → rumored`；
- 技能原理已确认：`hidden|rumored → known`。

每次变化写入 `AbilityEvent(type = revealed)`。隐藏能力在服务端响应投影前即过滤，不能依赖前端折叠或 CSS 隐藏；普通前端响应不得暴露隐藏能力名称、效果、限制或 ID。

## 11. 章末能力演化

现有章末抽取器增加能力增量，可提出：

- 新能力觉醒或习得；
- 族群技艺掌握；
- 先天能力缺失、强化或变异；
- 掌握程度提升；
- 受损、封印、恢复或失去；
- 可见性变化；
- 配角晋升为主要人物。

每条增量必须包含拥有者/能力标识、正文证据、证据消息尺度、前后状态和原因。后端逐条验证：

- 无正文依据的变化拒绝；
- 玩家锁定字段不可更新；
- 跨种族技艺引用无明确血脉/师承依据时拒绝；
- 普通训练不能无依据跨越多个掌握层级；
- 所有者与能力类型必须匹配；
- 失去只改变状态，不删除历史；
- 单条非法增量不阻断整章其他结算。

能力更新与事件写入同一事务；`dedupeKey` 保证断点续跑不会重复创建或升级。

后续普通人物只记录剧情已展示的能力。人物持续影响主线、形成独立目标或成为重要代理人时可晋升主要人物；晋升本身不会凭空补齐完整技能谱。

## 12. 界面设计

### 12.1 众生录·种族

新增“族裔能力”，分组展示：

- 先天能力：“族人默认继承”；
- 族群技艺：“需学习或传承”；
- 传闻能力：仅展示传闻文本；
- 隐藏能力：完全不下发。

已知项可展开查看效果、触发、代价、限制和状态。

### 12.2 众生录·主要人物

人物详情增加：

- 所属种族跳转；
- 势力与职务跳转；
- 当前目标与处境；
- 由服务端解析的实际能力谱；
- 默认继承、血脉例外、已掌握技艺和个人技能的来源标识；
- 按章节排列的能力沿革。

未覆写的继承能力不以人物副本重复存储或重复展示。

### 12.3 神谱

- 玩家神显示全部神权技能。
- 其他神只显示已知技能与传闻。
- 隐藏技能不在接口响应中出现。
- 次要神可暂时没有技能，随剧情渐进建档。

### 12.4 游戏内编辑

- 玩家可编辑玩家神技能、公开种族能力和已揭示技能。
- 修改字段自动标记“亲录”并默认锁定。
- 锁定按字段生效；AI 仍可更新未锁字段。
- 隐藏能力不能由普通接口读取或编辑。
- 有历史的能力删除转为 `deprecated`，不物理删除。

## 13. 服务边界与 API

能力逻辑拆分为：

- `ability-resolver`：计算当前实际能力。
- `ability-visibility`：生成已知、传闻、隐藏的投影。
- `ability-validator`：校验所有者、类型、来源、种族关系和字段锁。
- `ability-context`：构造叙事与幕后模型上下文。
- `ability-mutations`：创建、演化、揭示和写入事件。
- `deck-reference-validator`：校验草稿稳定引用。

新增 API：

- `POST /api/abilities`
- `PATCH /api/abilities/:id`
- `DELETE /api/abilities/:id`
- `GET /api/abilities/:id/history`

现有 API 扩展：

- 世界状态接口返回经过可见性过滤的神权能力。
- 众生录详情返回解析后的种族/人物能力。
- 开局接口将草稿 `ref` 转为数据库 ID。
- 叙事接口处理能力揭示信号。
- 章末结算应用通过验证的能力增量。

更新使用 `version` 或更新时间做乐观并发校验，防止 AI 结算覆盖玩家刚完成的修改。

## 14. 旧世界与存档兼容

数据库迁移只增加结构，不生成内容：

- 旧种族、人物与神明的能力列表为空。
- 旧世界正常进入、叙事和结算，不触发补全模型调用。
- 后续剧情明确展现能力时才渐进创建条目。
- 不自动生成旧世界主要人物名录。
- 新关联字段使用可空值或安全默认值。

导出格式加入能力、能力事件、人物种族关系与势力成员关系。旧格式导入时新增集合默认为空；新格式导入时重建所有 ID 和来源引用。完整私人存档保留隐藏能力，普通对局和百科接口仍严格过滤。

## 15. 测试策略

### 15.1 单元测试

- 先天能力默认继承；族群技艺不自动继承。
- 明确掌握、缺失、强化、变异、受损、封印覆写正确。
- `unawakened`、`sealed`、`lost` 不进入正常可用集合。
- 错误所有者、错误来源、跨时间线及非法跨种族引用被拒绝。
- 玩家字段锁有效。
- 状态与掌握层级跃迁符合规则。
- 相同 `dedupeKey` 不重复应用。

### 15.2 可见性测试

- 玩家神全部可见。
- 已知项完整显示；传闻项仅显示模糊文本。
- 隐藏能力的名称、内容和 ID 不进入前端响应。
- 行动建议不引用未知技能。
- 诸神后台回合可读自身隐藏技能。
- 合法见证后可分级揭示并写事件。
- 伪造其他时间线 ID 无效。

### 15.3 创世与开局集成测试

- 生成种族能力、神权技能及 6–12 位主要人物。
- 所有种族、势力、人物及技艺引用有效。
- 势力关键人物与人物实体一致。
- 重命名不破坏 `ref`；重掷保留锁定字段与引用。
- 开局事务完整落地；任一步失败整体回滚。

### 15.4 结算集成测试

- 习得、觉醒、提升、受损、封印、恢复和失去正确落库。
- 事件保存章节、消息尺度和正文依据。
- 无依据升级和非法技艺被拒绝，但不阻断其他增量。
- 断点续跑不重复创建或升级。
- 现有诸神回合、百科抽取、编年史与开新章流程不回归。

### 15.5 兼容与 UI 测试

- 旧世界无能力数据也能正常运行，且不会自动补全。
- 旧存档可导入；新存档往返后引用和历史完整。
- 种族能力类型、人物继承来源、传闻状态和能力沿革清晰可读。
- 人物与种族、势力可双向跳转。
- 桌面和移动抽屉均可用。
- 现有输入、时之仪与“结束本章”保持原样。

## 16. 最终验收场景

新建世界能够完成如下闭环：

> 创世生成种族、势力、主要人物与诸神能力谱 → 玩家在创世页检查并修改能力 → 开局后人物正确继承种族先天能力 → 人物只能使用实际掌握且当前可用的技能 → 隐藏技能不泄露 → 剧情中发动或习得技能 → 玩家手动结束本章 → 结算依据具体正文和时之仪尺度更新能力并记录沿革 → 下一章读取更新后的能力状态。
