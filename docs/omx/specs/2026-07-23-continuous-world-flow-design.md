# 连续世界游玩流程设计

日期：2026-07-23
状态：已确认，待实施

## 1. 目标

将当前“对话—结束本章—集中结算”和创世主“观测—改写”双通道，统一为无章节、单输入、连续演化的世界体验。

玩家只需要：

1. 用时之仪选择默认时间跨度；
2. 在唯一输入框中描述想看、想做或想改变的事；
3. 阅读结果并继续输入或点击“续写”。

系统在后台完成意图识别、轻量状态更新、重大事件结算与必要的现实分叉，不再要求玩家理解内部处理通道。

## 2. 已确认的产品原则

### 2.1 无玩家可见章节

删除玩家界面和玩家文案中的：

- 章节编号；
- 章节标题；
- “结束本章”按钮；
- 翻章建议；
- 全屏“岁月流转”结算演出。

现有 `Chapter` 数据结构暂时保留为内部消息分段和结算容器，避免同时重构消息、存档、能力沿革和现实克隆。任何内部章节切换都不得出现在玩家界面、Narrator 正文或操作提示中。

### 2.2 单一输入通道

诸神共世与创世主均使用同一套输入结构：

- 时之仪；
- 唯一文本输入框；
- “续写”；
- “发送”；
- 生成中的“搁笔”。

创世主模式删除：

- “观测世界 / 改写现实”页签；
- 改写范围选择；
- “观测 / 敕定现实”双按钮；
- 要求玩家预先判断输入类型的交互。

每条输入统一交给 LLM 理解。前端不展示内部意图分类。

### 2.3 时之仪是默认跨度，明确文字优先

时之仪保留五档：

- 一瞬；
- 一幕；
- 数年；
- 数十年；
- 百年。

处理规则：

1. 输入没有明确时间要求时，使用时之仪作为本轮默认叙事跨度。
2. 输入明确写出“三天后”“百年之后”“就在这一瞬”等时间要求时，文字优先。
3. 文字覆盖仅作用于本轮，不自动改变时之仪表盘。
4. 不弹出矛盾提示，也不要求玩家确认。

### 2.4 现实树仅承载追溯改写

以下行为沿当前现实继续，不创建分支：

- 观察当前世界；
- 世界内角色或化身的正常行动；
- 通过时之仪或明确文字推进未来；
- 从当前时间点开始建立新事实；
- 改变当前及未来的角色记忆或议程。

只有输入要求推翻、替换或重构已经成立的历史事实时，LLM 才返回内部的 `retroactive_rewrite` 意图。服务端随后：

1. 克隆当前现实；
2. 在子现实中应用追溯改写；
3. 将新现实设为活动现实；
4. 冻结并保留原现实；
5. 在新正文附近显示可点击的轻提示“⌘ 现实已分叉”。

不显示改写类型，不弹确认框，不向玩家暴露前瞻、仅记忆、追溯等内部枚举。

## 3. 玩家流程

```text
进入世界
  ↓
调整时之仪（可选）
  ↓
输入行动、观察或改变
  ↓
LLM 生成正文并返回结构化判定
  ↓
立即应用安全的小变化
  ↓
重大事件？
  ├─ 否 → 恢复输入，继续游玩
  └─ 是 → 短暂锁定输入并完整整理世界
               ↓
          自动恢复输入
```

玩家不再主动触发结算，也不需要判断当前内容属于“对话”“观测”还是“改写”。

## 4. 正式游玩界面

### 4.1 顶部标题

原“世界名 + 章节标题”改为：

> 世界名 · 当前纪元 · 当前时间

例如：

- `苍烬诸界 · 黑潮纪元 · 帝历三百二十七年`
- `无昼海 · 第三次退潮时代 · 双月重合之夜`
- `万机天庭 · 末法纪 · 距天门封闭已四百载`

`当前纪元`与`当前时间`由 LLM 按世界观自由书写，不规定统一纪年格式。

更新规则：

- 没有时间推进时保持不变；
- 时间推进时可更新当前时间；
- 发生纪元更替时同时更新纪元；
- 追溯改写后使用新现实重构后的纪元与时间；
- 切换现实后立即展示目标现实自己的纪元与时间；
- 两个字段持久化在现实状态中，刷新后不得丢失；
- 服务端只做非空、长度和字符安全校验，不规范化文案。

若旧存档缺少纪元或时间，使用现有主题纪元和最近编年史时间作为只读回退；首次成功生成或后台结算后写入正式现实状态。

### 4.2 输入区

默认显示：

1. 时之仪；
2. 唯一输入框；
3. “续写”按钮；
4. “发送”按钮。

生成正文时：

- 输入框与时之仪禁用；
- “发送”替换为“搁笔”；
- “续写”禁用。

完整后台结算时：

- 正文仍可阅读；
- 输入框、时之仪、续写和发送全部禁用；
- 输入区显示轻量状态“世界正在演化…”；
- 不显示全屏遮罩；
- 成功后自动恢复；
- 失败时显示“世界整理中断”，提供“继续整理世界”，不删除已生成正文。

### 4.3 保留的正文能力

继续保留：

- AI 行动建议；
- 朱批；
- 裁去；
- 异文与异文切换；
- 续写；
- 搁笔；
- 正文实体链接；
- 星图、编年史、神格或天外视界、现实树、设定集、众生录；
- 创世主化身；
- 日卷与烛光主题。

“续观”统一改名为“续写”。

## 5. 开场正文与创世演出并行

### 5.1 新流程

玩家在卡组页点击“创世”后，并行执行：

```text
视觉线程：播放创世演出

数据线程：
  物化世界
    ↓
  建立初始内部消息段
    ↓
  立即请求 opening 正文
    ↓
  保存 opening 正文
```

只有世界物化和 opening 正文都成功后，才进入正式游玩页。

### 5.2 演出末幕

删除“第一章 · 创世”，改为：

```text
世界名
当前纪元 · 当前时间
自此有史
```

若演出结束时 opening 尚未完成，保持简洁等待态：

> 世界正在落笔成形…

玩家点击“跳过”只跳过视觉演出，不跳过世界物化或 opening 生成。

### 5.3 幂等与失败恢复

- opening 使用稳定的生成用途标识和唯一约束，重复请求只能得到或续跑同一份开场。
- 世界物化成功但 opening 失败时，世界保持 `playing`，不得要求重新物化。
- 卡组页演出展示“开篇未成”，提供“重试开篇”。
- 刷新或从存档进入一个没有任何正文的已开局世界时，游玩页可以执行同一个幂等 opening 恢复流程。
- 删除游玩页当前基于“空章节”的普通自动 opening 逻辑，只保留上述异常恢复。

## 6. 统一 LLM 响应

Narrator 每轮除正文外返回内部结构化结果。概念形态如下：

```ts
type ContinuousNarrationResult = {
  narration: string;
  suggestions: string[];
  temporalState?: {
    era: string;
    time: string;
  };
  operation: "continue" | "retroactive_rewrite";
  immediateChanges: ImmediateChange[];
  significantEvent: boolean;
  settlementReasons: SettlementReason[];
};
```

### 6.1 `operation`

- `continue`：观察、正常行动、当前或未来新事实、向未来推进。
- `retroactive_rewrite`：推翻或替换已经成立的历史。

创世主可返回两种值。诸神共世固定为 `continue`，不能通过普通输入获得创世主的追溯改写权限。

### 6.2 `temporalState`

- 只有纪元或时间确实变化时才返回。
- 如果只更新一个字段，另一个字段沿用当前现实值。
- 服务端不能因 LLM 省略该字段而清空已有状态。
- 明确的玩家时间文字优先于时之仪，但最终标签仍由 LLM按世界风格表达。

### 6.3 `immediateChanges`

每轮只允许应用低风险、可直接验证的白名单变化，例如：

- 当前观察焦点；
- 当前地点；
- 当前场景出场状态；
- 化身进入或退出状态；
- 当前时间标签；
- 明确获得或失去的普通物品；
- 明确建立的短期关系提示；
- 最近事件摘要。

以下变化不得只靠轻结算直接落库，必须触发完整结算：

- 能力觉醒、习得、封印、恢复或失去；
- 神明或重要人物死亡；
- 势力建立、覆灭或易主；
- 神明位阶变化；
- 重要人物身份变化；
- 大规模关系重构；
- 纪元更替；
- 追溯改写；
- 需要更新多个相互引用实体的变化。

服务端必须对白名单、目标引用和活动现实归属重新校验，不直接信任模型输出。

## 7. 自动结算

### 7.1 触发条件

满足任一条件时触发完整结算：

- `significantEvent` 为真且至少有一个合法 `settlementReason`；
- 使用数年、数十年或百年尺度并实际发生明显时间推进；
- 发生纪元更替；
- 完成追溯改写；
- 检测到重要实体、势力、能力或神格变化；
- 自上次完整结算后累计达到 6 个 Narrator 回复，作为漏判兜底；
- 世界重新载入时存在未整理的消息。

服务端规则拥有最终决定权。模型标记用于提供语义线索，不能绕过确定性兜底。

### 7.2 完整结算内容

复用当前结算能力，但改为内部“世界整理”：

1. 世界内主神自主行动；
2. 状态、实体与能力抽取；
3. 编年史更新；
4. 实体热度衰减；
5. 保存检查点；
6. 轮转到新的内部消息段。

该过程不生成玩家可见章节标题，也不在正文中宣布翻章。

### 7.3 并发与锁定

采用已确认的短暂锁定方案：

1. 当前 Narrator 正文完整落库；
2. 服务端创建或续跑结算任务；
3. 前端锁定输入并显示“世界正在演化…”；
4. 世界级操作租约阻止叙事、结算、改写和现实切换并发污染；
5. 结算完成后重载活动现实状态并恢复输入。

不接受结算期间的新输入，不做客户端排队，也不允许下一轮读取未整理的旧状态。

### 7.4 失败恢复

- 结算结果先持久化，后续步骤幂等应用；
- 失败时保留正文和已经完成的步骤；
- “继续整理世界”从失败步骤续跑；
- 刷新页面后如发现活动世界有未完成任务，自动回到锁定恢复状态；
- 同一消息范围不得被重复抽取、重复生成编年史或重复推进诸神行动。

## 8. 消息编辑边界

取消玩家可见章节后，编辑边界改为“最近检查点”：

- 最近检查点之后的消息允许朱批、裁去和生成异文；
- 已被完整结算纳入检查点的消息视为历史证据，默认只读；
- 创世主修改旧历史应通过自然语言触发追溯改写；
- 诸神共世不能直接改写已经固化的历史；
- 前端不显示“已结算章节”，只在不可编辑的旧消息上使用简短提示“已成史”。

能力沿革与状态证据继续保存消息 ID 和内部记录段 ID；面向玩家的展示改用世界时间和事件描述，不显示章节编号。

## 9. 现实分叉数据流

创世主输入的统一处理顺序：

1. 使用当前现实上下文和时之仪生成结构化意图。
2. 若为 `continue`，按普通叙事保存消息和轻量变化。
3. 若为 `retroactive_rewrite`：
   - 不先把正文作为当前现实的普通消息落库；
   - 创建改写任务；
   - 克隆源现实并应用严格白名单补丁；
   - 在结果现实中保存改写后的正文；
   - 切换活动现实；
   - 标记结果消息包含源现实 ID 和改写任务 ID。
4. 前端重载新现实，并在结果正文旁显示“⌘ 现实已分叉”。

该流程保证旧现实中的消息不被原地篡改。

## 10. 数据模型演进

### 10.1 第一阶段：兼容迁移

- 保留 `Chapter` 表，将其视为内部 `segment`。
- 保留现有消息的 `chapterId` 外键。
- 在现实状态中正式持久化 `era` 和 `time`。
- 为内部段记录未整理消息数、最后检查点和结算状态。
- UI 和 Prompt 全面移除章节概念。

### 10.2 第二阶段：可选语义清理

待第一阶段稳定后，再评估：

- 将代码层的 `Chapter` 命名迁移为 `Segment` 或 `CheckpointWindow`；
- 将 `chapterIndex` 展示依赖替换为检查点序号或世界时间；
- 更新存档格式并保留旧版本导入迁移。

第二阶段不是本次首轮实施的前置条件。

## 11. 兼容性

- 旧世界继续使用现有章节数据，但进入新版 UI 后不显示章节。
- 当前打开章节中的消息作为最近未整理窗口；历史已结算章节作为既有检查点。
- v1/v2/v3 存档保持可导入。
- 导出格式暂时保留原章节字段，新增连续世界时间与检查点字段时提高存档小版本。
- 现实树拓扑、旧改写记录和隐藏信息不丢失。
- 诸神共世与创世主的世界模式不变量保持不变。

## 12. 测试要求

### 12.1 单元测试

- 明确时间文字覆盖时之仪但不改变表盘状态；
- `continue` 与 `retroactive_rewrite` 分类映射；
- 轻变化白名单和非法引用拒绝；
- 纪元、时间的部分更新与回退；
- 六轮兜底触发；
- 重大事件确定性触发；
- 最近检查点前后消息的编辑权限；
- “续观”到“续写”的模式统一。

### 12.2 集成测试

- 创世物化与 opening 并行编排；
- opening 重试不重复生成消息；
- 动画结束前 opening 完成和动画结束后 opening 完成两种时序；
- 世界物化成功、opening 失败后的恢复；
- 每轮轻结算写入与完整结算升级；
- 完整结算期间拒绝新聊天；
- 结算失败断点续跑；
- 追溯改写自动克隆现实且不修改源现实；
- 推进未来不创建现实分支；
- 切换现实后标题时间正确恢复。

### 12.3 UI 测试

- 两种模式都只有一个输入框；
- 不出现结束本章、翻章提示、章节标题或改写范围控件；
- 后台结算只显示非阻塞轻状态；
- 现实分叉提示可打开现实树；
- 顶部标题按“世界名 · 纪元 · 时间”渲染；
- 跳过演出后仍等待 opening。

## 13. 验收标准

满足以下条件视为完成：

1. 玩家从进入世界到长期游玩无需接触章节概念。
2. 玩家无需选择观测或改写通道。
3. 创世主修改既有历史时自动创建现实分支，其他输入不误建分支。
4. 时间推进默认受时之仪控制，明确文字可仅在本轮覆盖。
5. 每轮安全小变化及时落库，重大变化自动完整整理。
6. 完整整理期间锁定输入，完成后自动恢复，失败可续跑。
7. 点击“创世”后，开场正文在演出期间开始生成；进入游戏时已有正文。
8. 顶部始终显示世界名、自由格式纪元和自由格式时间。
9. 旧世界、现有现实树和现有存档仍可使用。
