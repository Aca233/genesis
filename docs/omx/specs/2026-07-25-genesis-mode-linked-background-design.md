# 创世模式联动背景设计

## 目标

在首页现有“星图古卷”日／烛双主题背景之上，增加能够随世界模式切换的氛围图层，让“诸神共世”与“创世主”在玩家阅读说明前就具有不同的视觉性格。

本设计只增强首页创世表单的视觉反馈，不改变世界模式语义、创世请求、素材选择、典籍上传或主题系统。模式图层必须退居文字和表单之后，不能降低神谕输入、模式说明与错误信息的可读性。

## 已确认方案

采用“2 张现有主题底图 × 2 张新增模式叠层”的组合方式：

- 底层继续由现有日卷／烛光星图背景承担纸张、色温和整体环境；
- 上层新增“诸神共世”与“创世主”两张模式氛围图；
- 切换日／烛主题时不更换模式资产，只通过主题变量调整模式图层的亮度、透明度、色温和混合效果；
- 切换世界模式时，两张模式图层交叉淡入；
- 不为四种组合分别生成四张完整背景。

这种结构保持既有双主题构图稳定，只增加两项资产，并能组合出以下四种状态：

| 主题 | 世界模式 | 视觉表现 |
| --- | --- | --- |
| 日卷 | 诸神共世 | 群星核、浅金星轨与均衡环阵 |
| 烛光 | 诸神共世 | 多枚烛金星核与深褐神座轮廓 |
| 日卷 | 创世主 | 单一明亮星核与清冷巨环 |
| 烛光 | 创世主 | 孤独炽金核心与幽暗世界涟漪 |

## 视觉语言

两张模式图均采用抽象象征构图，不绘制清晰人物，以兼容修仙、奇幻、科幻及混合题材。

### 诸神共世

- 由 5–7 枚大小与明度不同的星核构成不完全环阵；
- 中央保留一个克制的空位，暗示玩家将加入神谱；
- 多道星轨彼此交错，表达多神关系、制衡与共同塑造世界；
- 左右边缘可有极淡的神座、星门或仪式环轮廓，但不能形成具体建筑；
- 视觉重量分布在画面四周，上方略强，下方表单操作区保持平静。

### 创世主

- 只保留一枚主要星核，作为唯一创世核心；
- 以一道巨型圆环或世界纺轮环绕核心；
- 从核心向外扩散星云、地貌生成纹理或宇宙涟漪；
- 周围保留更大面积的幽暗留白，表达孤独观察与绝对创世；
- 与“诸神共世”使用相同视角、画布尺寸和主体坐标，使模式切换像同一宇宙结构发生变化，而非跳转到另一幅场景。

### 共同限制

- 不出现人物、面孔、手、动物、具体建筑或明确武器；
- 不出现文字、字母、数字、徽标、水印或伪文字；
- 不使用可识别的现实宗教符号；
- 不生成按钮、输入框、卡片边框或其他 UI；
- 避免高饱和霓虹、密集粒子、大片纯黑和刺眼高光；
- 画面不能预设某一具体世界题材。

## 构图与响应式安全区

- 两张母版采用相同尺寸与构图坐标，建议尺寸为 `2048 × 1152`；
- 主要星核与环阵位于画面中央偏上区域，避开首页主要输入与操作位置；
- 中央表单覆盖区域必须低频、低对比，不放置星核、圆环交点或强烈纹理；
- 左右装饰允许在桌面宽屏显示，并允许被窄屏 `cover` 裁切；
- 中央主体是移动端安全区，裁去两侧后仍能分辨当前模式；
- 画面四周自然延伸，不出现硬边框、相框或独立画布边缘；
- 模式图层应能覆盖整页视口，但其视觉强度在首页创世面板后方被保护遮罩进一步压低。

## 资产与交付

新增两项网页资产：

- `public/images/backgrounds/genesis-mode-pantheon.webp`
- `public/images/backgrounds/genesis-mode-creator.webp`

同时保留无损母版：

- `art/backgrounds/genesis-mode-pantheon-source.png`
- `art/backgrounds/genesis-mode-creator-source.png`

资产生成要求：

1. 先生成“诸神共世”母版并检查构图、安全区和伪文字；
2. 以其为构图参考生成或编辑“创世主”母版，严格保持视角、主体中心和整体空间尺度；
3. 检查两图切换时是否存在明显视角跳动；
4. 必要时进行局部清理、对齐和对比度压制；
5. 输出优化 WebP，并保留 PNG 母版；
6. 两项 WebP 都在首页预加载，避免首次模式切换时闪白。

模式资产不需要透明通道。网页端通过混合模式、遮罩渐变与受控透明度将其融入现有背景，这比保留大尺寸半透明 PNG 更利于体积控制。

## 页面分层

首页背景由后至前分为：

1. 现有日卷／烛光星图背景；
2. 当前模式的氛围图层；
3. 主题相关的色温与可读性遮罩；
4. 标题、模式卡片、神谕输入、素材入口和操作按钮。

模式图层为纯装饰：

- `aria-hidden="true"`；
- `pointer-events: none`；
- 不进入页面语义或键盘焦点顺序；
- 图片加载失败时不显示模式图层，现有日／烛背景继续工作；
- 不阻塞创世表单的初始渲染和提交。

首页创世面板继续使用半透明纸张表面。面板背景可略微降低不透明度，让模式氛围可感知，但必须通过局部暗化／亮化遮罩保证所有文字达到现有可读性水平。

## 状态与交互

- `worldMode` 仍是唯一模式状态源，不新增并行视觉状态；
- 页面同时挂载两张模式图层，以 `worldMode` 控制激活态，避免切换时重新下载和布局；
- 模式切换采用约 `600ms` 的交叉淡入，推荐只动画 `opacity`；
- 切换过程中不移动背景、不缩放主体，不产生视差；
- 日／烛主题通过现有主题属性或 CSS 变量调整模式图层，不复制 React 状态；
- 创建任务期间模式控件被锁定后，背景保持当前已选模式；
- `prefers-reduced-motion: reduce` 下关闭过渡，直接显示目标模式；
- 模式图层不得改变表单尺寸、页面滚动位置或可点击区域。

## 组件边界

本轮实现应保持职责清晰：

- `PlayBackground` 继续只负责通用日／烛星图底层；
- 新增独立的首页模式背景组件 `GenesisModeBackground`，接收 `mode`，只渲染两张装饰图层；
- 首页负责把现有 `worldMode` 传给模式背景组件；
- CSS 负责四种主题／模式组合的视觉调校和降级；
- 不把世界模式逻辑塞入通用 `PlayBackground`，避免其他页面无意加载首页专用资产。

## 错误处理与性能

- 任一模式图片加载失败时，隐藏失败图层，保留现有主题背景和表单；
- 两张图均使用稳定静态路径，避免模式切换触发网络请求；
- WebP 输出需在可接受画质下压缩，避免首页资源体积接近原始 PNG；
- 动画仅改变合成友好的 `opacity`，不持续动画滤镜或背景位置；
- 移动端降低模式图层强度，避免小屏上纹理压迫表单；
- 不引入画布、WebGL、粒子系统或常驻计时器。

## 验证与测试

### 自动化

- 组件测试确认模式组件同时渲染两种图层，且当前模式获得正确激活态；
- 确认装饰容器具有 `aria-hidden`，不会创建交互控件；
- 首页测试确认 `worldMode` 传递给模式背景，模式切换仍只更新既有状态；
- 现有创世请求测试继续确认模式值和提交负载不变；
- 源码 ESLint、相关 Vitest 与生产构建通过。

### 视觉验收

分别检查日卷／烛光下的“诸神共世”和“创世主”四种组合：

- 两种模式能在不读文字时被感知，但背景不盖过标题和表单；
- 模式切换没有视角跳动、闪白或明显接缝；
- 日／烛切换后，模式含义不变，色温能自然融入对应底图；
- 桌面宽屏仍可看到侧翼结构；
- `390px` 手机宽度无横向溢出，中央主体不被完全裁掉；
- 神谕占位文字、模式说明、错误信息和禁用状态保持清晰；
- 减少动态效果偏好下没有交叉动画；
- 图片缺失时仍能正常完成创世。

## 本轮范围

包含：

- 两张模式母版与两张优化 WebP；
- 首页模式背景组件；
- 日／烛主题和两种模式的组合样式；
- 模式切换、移动端、降级和减少动态效果处理；
- 必要的组件与首页测试。

不包含：

- 为四种组合生成四张完整背景；
- 将模式图层扩展到创世进度、卡组、仪式或主游玩页；
- 世界专属动态背景；
- 动态粒子、视差、WebGL 或音效；
- 改造世界模式业务逻辑；
- 根据玩家神谕实时生成背景。
