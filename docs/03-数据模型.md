# 03 · 数据模型

## 0. 双模式与现实树数据模型增补

### 不变量

- `World.mode ∈ {pantheon, creator}` 且不可变。
- Pantheon 活动现实恰有一个玩家神；Creator 所有现实均有零个玩家神。
- `World.activeTimelineId` 必须属于本世界；现实树唯一根、同世界父子、无环。
- `RealityRewrite.sourceTimelineId/resultTimelineId` 与 `Timeline.parentId/forkRewriteId` 必须一致。

### Timeline

`parentId / forkChapter / forkRewriteId / branchName / branchSummary / realityState / observerState` 描述现实节点。`observerState` 包含焦点类型/ID、时间标签、`omniscient|limited` 和活动化身 ID。

### RealityRewrite

保存敕令、归一化 scope、来源章节、白名单 plan、结果现实、摘要、幂等键和可恢复状态。租约 token/error 是运行态私有字段，不进入 owner archive。

### 图克隆规则

章节、消息、神、实体、栏目、能力、能力事件、成员关系、编年史和征兆全部生成新 ID；关系字段以及 snapshot/message meta/variants 内嵌 ID 同步重映射。GenerationRequest 和操作租约不克隆，消息中的 request-only 元数据移除；发现源现实 ID 残留即失败回滚。

### 存档

私有 archive v3 保存 mode、全部现实节点、改写记录、观察状态、Creator 化身、隐藏栏目/能力/编年史与活动现实。v1/v2 缺失字段时按 Pantheon 构造单根现实。导入拒绝环、跨世界父节点、缺失活动节点、rewrite 结果不匹配和 Creator 玩家神。


Prisma 风格伪 schema（最终以实现时的迁移为准）。所有表带 `user_id`（单用户期恒为 `'local'`），带 `created_at/updated_at`。

## 1. 存档与时间线（树状分叉模型）

```prisma
model World {            // 一个「存档」= 一个世界
  id            String  @id @default(cuid())
  user_id       String  @default("local")
  name          String                    // 世界名（AI 起，可改）
  genesis_input String                    // 原初神谕（玩家第一句话）
  status        String  // draft | playing | concluded(已成史)
  theme_card    Json    // 主题卡：纪年名、位阶命名、措辞
  style_card    Json    // 叙事风格卡：预设名+文体规则
  cosmology     Json    // 宇宙论卡
  fusion_axiom  Json?   // 融合公理卡
  timelines     Timeline[]
  active_timeline_id String?
}

model Timeline {         // 时间线（M3 分叉；M1/M2 恒一条）
  id          String @id
  world_id    String
  parent_id   String?      // 自哪条时间线分叉
  fork_chapter Int?        // 自第几章分叉
  chapters    Chapter[]
  entities    Entity[]
  gods        God[]
  abilities   Ability[]
  chronicles  ChronicleEntry[]
}

model Chapter {
  id           String @id
  timeline_id  String
  index        Int
  title        String?
  summary      String?     // 章末史官小结
  settle_state String      // open | settling:<step> | settled   （断点续跑）
  snapshot     Json?       // 章快照（分叉用：实体/神/编年史的物化状态）
  messages     Message[]
}

model Message {
  id          String @id
  chapter_id  String
  role        String   // player | narrator
  content     String
  scale       String   // scene | era | epoch   （发送时的尺度档）
  variants    Json?    // 异文候选 [{content, chosen}]
  meta        Json?    // 建议列表、揭示事件id、能力揭示信号、实体链接span等
  index       Int
  ability_events AbilityEvent[] // 以本消息为正文证据的能力沿革
}
```

> `Chapter` 是历史兼容的数据库名称，产品语义是**内部检查点窗口**。正式 UI 不展示 index/title；新窗口 `title=null`，顶部标题来自 `World.name + RealityState.currentEra + ObserverState.timeLabel`。

- **连续读取**：state API 展平最近四个内部窗口，最多 80 条；只有当前 `settle_state=open` 且属于活动现实的消息可编辑。
- **时间与轻变化**：Narrator meta 的白名单补丁分别写入 `RealityState.currentEra`、`ObserverState.timeLabel` 与当前现实实体；任一非法引用使整个事务回滚。
- **自动整理**：重大变化或六轮兜底将 meta 标记 `settlementRequired`，状态机沿用 `settle_state` 幂等恢复。
- **追溯分叉**：只有 Creator 推翻既成历史时创建 RealityRewrite；源现实不写临时 player/Narrator 消息。结果消息标记为需要整理。
- **裁去/朱批/异文**：仅允许当前开放窗口；此前窗口和冻结现实由服务端统一返回 409。

## 2. 诸神

```prisma
model God {
  id           String @id
  timeline_id  String
  name         String
  aliases      String[]     // 检索用
  tier         String       // 主神 major | 次要 minor | player
  is_player    Boolean @default(false)
  rank         String       // 位阶（主题卡命名映射前的内部枚举：ember..sovereign）
  domains      String[]     // 领域关键词
  persona      Json         // 人格卡（可见）
  voice        Json         // 声纹卡（可见）：语癖/称呼/口头禅/禁语
  agenda       Json         // 议程卡（默认隐藏）：goals, stance_to_player{level,motive}, schemes[]
  agenda_revealed Boolean @default(false)
  relations    Json         // { god_id|entity_id: {label: 敌对|竞争|中立|盟友|隶属, note} }
  faith_scope  String?      // 信仰范围一句话
  codex_entity_id String?   // 关联百科条目（神也在众生录有卡）
  abilities     Ability[]   // 玩家神/主神的 divine 神权
}
```

## 3. 百科（Codex）= 结构化状态卡

```prisma
model Entity {
  id           String @id
  timeline_id  String
  type         String   // faction | character | race | place | artifact | cult
  name         String
  aliases      String[]                 // 本名+别名+称号（实体索引的匹配源）
  emblem_seed  String                   // 程序纹章种子（名字哈希）
  image_url    String?                  // 玩家上传；预留 AI 生图
  starred      Boolean @default(false)  // 玩家标星→永不降档
  is_chosen    Boolean @default(false)  // 神选者→永不降档/压缩
  is_major_character Boolean @default(false) // 创世 6–12 位主要人物，后续人物可晋升
  race_id      String?                  // character 的主种族；旧人物可为空
  heat         String  @default("active") // active | dormant
  scene_presence Boolean @default(false) // 当前在场（强制注入）
  summary      String                   // 摘要卡内容（dormant 时的全部）
  sections     EntitySection[]
  abilities    Ability[]                // 种族模板或人物个体能力
  memberships  EntityMembership[]       // 人物—势力多对多关系
  locked_paths String[]                 // player_locked 字段路径
}

model EntitySection {     // 栏目 = 迷雾与更新的最小粒度
  id         String @id
  entity_id  String
  key        String   // overview|territory|faith|lifespan|beliefs|... 按类型模板
  content    Json
  revealed   Boolean @default(true)   // false → 「传闻/经卷残缺」样式
  rumor_text String?                  // 未揭示时展示的传闻（可为误导）
  player_locked Boolean @default(false)
}
```

- 六类实体的栏目模板在代码中以常量定义（01 篇 9.1 表）；`EntitySection.key` 受模板约束。
- 人物类固有栏目含 `lifespan {born_year, expected, dead?}`、`faith_history[]`、`voice`。
- 实体专属编年史不落此表——由 ChronicleEntry 反查（见下）。
- `EntityMembership { character_id, faction_id, role, is_primary }` 取代势力关键人物的纯姓名运行时关联；同一人物可属于多个势力。
- 新世界以稳定引用物化 6–12 位主要人物；旧世界不自动回填 `is_major_character`、`race_id` 或成员关系。

## 4. 结构化能力与沿革

```prisma
model Ability {
  id              String @id
  timeline_id     String
  entity_id       String?  // race 或 character
  god_id          String?  // player/major god
  source_ability_id String? // 人物技艺掌握或先天覆写所指的种族模板
  name            String
  kind            String   // racial_innate | racial_tradition | personal | divine
  effect          String
  trigger         String
  cost             String
  limitations      String
  mastery          String   // unawakened | novice | adept | expert | master
  state            String   // normal | enhanced | impaired | sealed | lost | deprecated
  visibility       String   // known | rumored | hidden
  rumor_text       String?
  bloodline_justification String?
  locked_fields    String[]
  version          Int      // 乐观并发控制
  events           AbilityEvent[]
}

model AbilityEvent {
  id          String @id
  ability_id  String
  chapter_id  String
  message_id  String?  // 最直接的正文证据
  type        String    // awakened | learned | improved | mutated | impaired |
                       // sealed | restored | lost | revealed | deprecated
  before      Json?
  after       Json?
  evidence    String
  scale       String    // 证据消息自己的 scene | era | epoch
  dedupe_key  String @unique
  created_at  DateTime
}

model EntityMembership {
  id           String @id
  character_id String
  faction_id   String
  role         String
  is_primary   Boolean
  @@unique([character_id, faction_id])
}
```

约束与解析语义：

- `entity_id` 与 `god_id` 必须恰有一个非空，且所有者、来源与能力必须同属一条时间线。
- 种族模板只能是 `racial_innate` / `racial_tradition`；人物来源记录必须指向同类型、同时间线的种族模板；个人技能只属于人物，神权只属于神明。
- 人物有效能力 = 主种族当前可用先天能力 + 人物对先天来源的覆写 + 明确掌握的族群技艺 + 个人技能。族群技艺绝不因 `race_id` 自动生效。
- `unawakened`、`sealed`、`lost`、`deprecated` 不进入正常可用集合；`impaired` 仍可用但携带受损限制。掌握程度只影响叙事，不换算数值。
- 能力失去或废弃时保留记录与事件沿革；`dedupe_key` 使章末断点续跑不会重复演化。
- 玩家投影中，`known` 返回完整字段；`rumored` 只返回传闻安全摘要；`hidden` 整项过滤。私有存档导出例外：必须保留完整数据。

## 5. 编年史

```prisma
model ChronicleEntry {
  id          String @id
  timeline_id String
  chapter_index Int
  year_label  String    // 纪年文本（主题卡的纪年体系）
  text        String    // 史官笔法 2-3 句
  entity_ids  String[]  // 涉及实体（实体专属编年史 = 按此筛选）
  god_ids     String[]
  revealed    Boolean   // false = 诸神隐藏行动（幕后大事记）
  revealed_at_chapter Int?   // 「于第N章揭晓」
  source      String    // narrative | pantheon(诸神回合) | manual
}
```

- **隐藏大事记**与可见编年史同表（`revealed` 区分），揭示即翻转并记录揭晓章。
- 待织入征兆队列：`OmenQueue { id, god_id, text, consumed }`——叙事生成时取未消费项注入，输出后标记消费。

## 6. 世界书（ST 兼容）

```prisma
model LorebookEntry {
  id          String @id
  world_id    String
  keys        String[]   // ST 触发词
  content     String
  enabled     Boolean
  st_extra    Json       // 保留 ST 原始字段（priority/position 等），导出时还原
  source      String     // imported | generated
}
```

- **导入**：解析 ST worldbook v2 JSON → 逐条入库，未识别字段全存 `st_extra` 保证导出不丢。
- **导出**：两路——(a) 原样还原导入条目 + (b) 将世界卡/百科条目**编译**为 ST entries（name/aliases→keys，栏目文本→content），供社区回流。

## 8. 导出格式

- **存档 JSON v2**：`{version: 2, world, timelines[…全量]}`。每条时间线完整导出人物 `race_id`、`abilities`（含 `source_ability_id`）、`memberships` 与 `ability_events`（含章节/消息证据）；私有导出不按迷雾可见性过滤。
- **导入兼容**：接受 `version: 1 | 2`。v1 缺少能力、沿革和成员关系时按空集合解析；v2 导入先预生成所有新 ID，再按实体/神/章节/消息 → 能力/成员关系 → 能力事件的顺序写入，修复来源与外键引用。
- **旧世界策略**：不迁移、不回填、不一键补齐主要人物或能力。旧世界空能力集合可以继续游玩，后续仅在剧情明确展示且有证据时渐进建档。
- **《创世史》**：按章拼装（章题+正文定稿+章末小结），Markdown 直出；EPUB 用 epub 生成库打包，书名《创世史·〈世界名〉》。
- **模板**（M3）：世界卡组 + 世界书条目（不含对局正文/编年史），发布到 `Template` 表（含 `moderation_state` 预留字段）。

## 9. 万象藏库

```prisma
model MaterialCard {
  id                 String @id
  user_id            String
  kind               String
  name               String
  summary            String
  favorite           Boolean
  hidden             Boolean
  source_world_id    String? // World 删除时 SET NULL
  source_world_name  String  // 永久保留来源名称
  source_kind        String
  source_ref         String
  default_version_id String?
  last_used_at       DateTime?
  @@unique([user_id, source_kind, source_ref])
}

model MaterialVersion {
  id                String @id
  card_id           String
  version           Int
  name              String
  note              String?
  content           Json   // 完整、不可变的规范快照
  dependencies      Json
  schema_version    Int
  is_initial        Boolean
  parent_version_id String?
  @@unique([card_id, version])
}
```

- `GenesisTask.material_selection` 保存启动时的完整版本内容、依赖决定、能力拥有者、模式和优先级；它是独立 JSON 快照，不外键关联可删除的素材版本。
- `God.material_ref`、`Entity.material_ref`、`Ability.material_ref` 把开局卡组稳定 ref 延续到运行态；剧情新对象以 `worldId:runtime:sourceType:sourceId` 形成稳定来源键。
- `World.material_archive_status/error` 记录开局后自动收录状态；归档失败不回滚已经成功的开局，可从存档页重试。
- `MaterialVersion` 只追加、不可原位更新。默认版本和最后一个版本不能直接删除；先切换默认版本后才能删除旧的非最终版本。
