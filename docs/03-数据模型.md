# 03 · 数据模型

Prisma 风格伪 schema（最终以实现时的迁移为准）。所有表带 `user_id`（单用户期恒为 `'local'`），带 `created_at/updated_at`。

## 1. 存档与时间线（树状分叉模型）

```prisma
model World {            // 一个「存档」= 一个世界
  id            String  @id @default(cuid())
  user_id       String  @default("local")
  name          String                    // 世界名（AI 起，可改）
  genesis_input String                    // 原初神谕（玩家第一句话）
  status        String  // draft | playing | concluded(已成史)
  theme_card    Json    // 主题卡：纪年名、位阶命名、措辞
  style_card    Json    // 叙事风格卡：预设名+文体规则
  cosmology     Json    // 宇宙论卡
  fusion_axiom  Json?   // 融合公理卡
  timelines     Timeline[]
  active_timeline_id String?
}

model Timeline {         // 时间线（M3 分叉；M1/M2 恒一条）
  id          String @id
  world_id    String
  parent_id   String?      // 自哪条时间线分叉
  fork_chapter Int?        // 自第几章分叉
  chapters    Chapter[]
  entities    Entity[]
  gods        God[]
  chronicles  ChronicleEntry[]
}

model Chapter {
  id           String @id
  timeline_id  String
  index        Int
  title        String?
  summary      String?     // 章末史官小结
  settle_state String      // open | settling:<step> | settled   （断点续跑）
  snapshot     Json?       // 章快照（分叉用：实体/神/编年史的物化状态）
  messages     Message[]
}

model Message {
  id          String @id
  chapter_id  String
  role        String   // player | narrator
  content     String
  scale       String   // scene | era | epoch   （发送时的尺度档）
  variants    Json?    // 异文候选 [{content, chosen}]
  meta        Json?    // 建议列表、揭示事件id、实体链接span等
  index       Int
}
```

- **分叉**：以 `Chapter.snapshot` 为起点新建 Timeline，复制截至该章的实体/神/编年史物化状态；旧线不动。
- **裁去**：删除章内尾部 Message；**朱批**：改 content（保留 `meta.edited=true`）。

## 2. 诸神

```prisma
model God {
  id           String @id
  timeline_id  String
  name         String
  aliases      String[]     // 检索用
  tier         String       // 主神 major | 次要 minor | player
  is_player    Boolean @default(false)
  rank         String       // 位阶（主题卡命名映射前的内部枚举：ember..sovereign）
  domains      String[]     // 领域关键词
  persona      Json         // 人格卡（可见）
  voice        Json         // 声纹卡（可见）：语癖/称呼/口头禅/禁语
  agenda       Json         // 议程卡（默认隐藏）：goals, stance_to_player{level,motive}, schemes[]
  agenda_revealed Boolean @default(false)
  relations    Json         // { god_id|entity_id: {label: 敌对|竞争|中立|盟友|隶属, note} }
  faith_scope  String?      // 信仰范围一句话
  codex_entity_id String?   // 关联百科条目（神也在众生录有卡）
}
```

## 3. 百科（Codex）= 结构化状态卡

```prisma
model Entity {
  id           String @id
  timeline_id  String
  type         String   // faction | character | race | place | artifact | cult
  name         String
  aliases      String[]                 // 本名+别名+称号（实体索引的匹配源）
  emblem_seed  String                   // 程序纹章种子（名字哈希）
  image_url    String?                  // 玩家上传；预留 AI 生图
  starred      Boolean @default(false)  // 玩家标星→永不降档
  is_chosen    Boolean @default(false)  // 神选者→永不降档/压缩
  heat         String  @default("active") // active | dormant
  scene_presence Boolean @default(false) // 当前在场（强制注入）
  summary      String                   // 摘要卡内容（dormant 时的全部）
  sections     EntitySection[]
  locked_paths String[]                 // player_locked 字段路径
}

model EntitySection {     // 栏目 = 迷雾与更新的最小粒度
  id         String @id
  entity_id  String
  key        String   // overview|territory|faith|lifespan|beliefs|... 按类型模板
  content    Json
  revealed   Boolean @default(true)   // false → 「传闻/经卷残缺」样式
  rumor_text String?                  // 未揭示时展示的传闻（可为误导）
  player_locked Boolean @default(false)
}
```

- 六类实体的栏目模板在代码中以常量定义（01 篇 9.1 表）；`EntitySection.key` 受模板约束。
- 人物类固有栏目含 `lifespan {born_year, expected, dead?}`、`faith_history[]`、`voice`。
- 实体专属编年史不落此表——由 ChronicleEntry 反查（见下）。

## 4. 编年史

```prisma
model ChronicleEntry {
  id          String @id
  timeline_id String
  chapter_index Int
  year_label  String    // 纪年文本（主题卡的纪年体系）
  text        String    // 史官笔法 2-3 句
  entity_ids  String[]  // 涉及实体（实体专属编年史 = 按此筛选）
  god_ids     String[]
  revealed    Boolean   // false = 诸神隐藏行动（幕后大事记）
  revealed_at_chapter Int?   // 「于第N章揭晓」
  source      String    // narrative | pantheon(诸神回合) | manual
}
```

- **隐藏大事记**与可见编年史同表（`revealed` 区分），揭示即翻转并记录揭晓章。
- 待织入征兆队列：`OmenQueue { id, god_id, text, consumed }`——叙事生成时取未消费项注入，输出后标记消费。

## 5. 世界书（ST 兼容）

```prisma
model LorebookEntry {
  id          String @id
  world_id    String
  keys        String[]   // ST 触发词
  content     String
  enabled     Boolean
  st_extra    Json       // 保留 ST 原始字段（priority/position 等），导出时还原
  source      String     // imported | generated
}
```

- **导入**：解析 ST worldbook v2 JSON → 逐条入库，未识别字段全存 `st_extra` 保证导出不丢。
- **导出**：两路——(a) 原样还原导入条目 + (b) 将世界卡/百科条目**编译**为 ST entries（name/aliases→keys，栏目文本→content），供社区回流。

## 6. 设置与日志

```prisma
model Settings {

  backstage_slot Json?
  embedding_slot Json?  // 可选向量增强
  prefs      Json       // 建议开关/翻章建议/烛光模式/文风预设
}

model LlmCall {
  id String @id
  task String       // narrative|genesis|pantheon|extract|chronicle
  slot String
  duration_ms Int
  ok Boolean
  error String?
  created_at DateTime
}
```

## 7. 导出格式

- **存档 JSON**：`{version, world, timelines[…全量]}`，导入时按 version 迁移。
- **《创世史》**：按章拼装（章题+正文定稿+章末小结），Markdown 直出；EPUB 用 epub 生成库打包，书名《创世史·〈世界名〉》。
- **模板**（M3）：世界卡组 + 世界书条目（不含对局正文/编年史），发布到 `Template` 表（含 `moderation_state` 预留字段）。
