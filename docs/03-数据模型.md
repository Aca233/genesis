# 03 · 数据模型

> 更新日期：2026-07-27

## 0. 双模式与现实树数据模型增补

### 不变量

- `World.mode ∈ {pantheon, creator}` 且不可变。
- Pantheon 活动现实恰有一个玩家神；Creator 所有现实均有零个玩家神。
- `World.activeTimelineId` 必须属于本世界；现实树唯一根、同世界父子、无环。
- `RealityRewrite.sourceTimelineId/resultTimelineId` 与 `Timeline.parentId/forkRewriteId` 必须一致。

### Timeline

`parentId / forkChapter / forkRewriteId / branchName / branchSummary / realityState / observerState` 描述现实节点。`observerState` 包含焦点类型/ID、时间标签、`omniscient|limited`、活动化身 ID，以及同一时刻至多一个 `focusedEventId`。旧数据缺少该字段时按 `null` 读取。

### RealityRewrite

保存敕令、归一化 scope、来源章节、白名单 plan、结果现实、摘要、幂等键和可恢复状态。租约 token/error 是运行态私有字段，不进入 owner archive。

### 图克隆规则

章节、消息、神、实体、栏目、能力、能力事件、成员关系、实体关系、编年史、征兆、持续事件、世界动态和图标分配全部生成新 ID；关系字段以及 snapshot/message meta/variants 内嵌 ID 同步重映射。事件分叉必须重映射 `parentEventId / originActivityId / originMessageId / latestMessageId / participantIds`，动态必须重映射 `eventId / actorId / targetIds / subjectIds / sourceMessageId`，观察状态同步重映射 `focusedEventId`。将临之事（CanonEvent）只含卡组稳定 ref、不含任何图 ID，逐字段照抄即可；图标分配按 `subjectType` 重映射 `subjectId`，无法映射的分配记日志后跳过。GenerationRequest 和操作租约不克隆，消息中的 request-only 元数据移除；发现源现实 ID 残留即失败回滚。

### 存档

私有 archive v4 保存 mode、全部现实节点、改写记录、观察状态、Creator 化身、隐藏栏目/能力/编年史、`WorldEvent`、`WorldActivity`、实体关系、征兆（含 `kind`）、将临之事、图标主题与图标分配以及活动现实；顶层附带按世界实际使用图标生成的 `iconCreditsMarkdown` 致谢文本。导入仅接受 `version: 4`，其余版本一律 400「存档版本不受支持」；`iconCreditsMarkdown` 导入时接受但忽略，再次导出时重新生成。导出保留 hidden 世界动态，但不导出任务租约、`outputSnapshot` 或内部错误。导入拒绝环、跨世界父节点、缺失活动节点、rewrite 结果不匹配和 Creator 玩家神。


Prisma 风格伪 schema（最终以实现时的迁移为准）。所有表带 `user_id`（单用户期恒为 `'local'`），带 `created_at/updated_at`。

## 1. 存档与时间线（树状分叉模型）

```prisma
model World {            // 一个「存档」= 一个世界
  id            String  @id @default(cuid())
  user_id       String  @default("local")
  name          String                    // 世界名（AI 起，可改）
  genesis_input String                    // 原初神谕（玩家第一句话）
  status        String  // draft | playing | concluded(已成史)
  theme_card    Json    // 主题卡：纪年名、位阶命名、措辞
  style_card    Json    // 叙事风格卡：预设名+文体规则
  cosmology     Json    // 宇宙论卡
  fusion_axiom  Json?   // 融合公理卡
  icon_theme    Json?   // 世界图标主题（类别映射 + lockedAssignments，见 §10）
  icon_theme_revision Int      // 主题版次
  icon_theme_operation_key String?  // 主题生成幂等键
  timelines     Timeline[]
  active_timeline_id String?
}

model Timeline {         // 时间线（M3 分叉；M1/M2 恒一条）
  id          String @id
  world_id    String
  parent_id   String?      // 自哪条时间线分叉
  fork_chapter Int?        // 自第几章分叉
  chapters    Chapter[]
  entities    Entity[]
  gods        God[]
  abilities   Ability[]
  chronicles  ChronicleEntry[]
  omens       OmenQueue[]
  canon_events CanonEvent[]      // 将临之事（见 §5.1）
  icon_assignments IconAssignment[] // 图标分配（见 §10）
}

model Chapter {
  id           String @id
  timeline_id  String
  index        Int
  title        String?
  summary      String?     // 章末史官小结
  settle_state String      // open | settling:<step> | settled   （断点续跑）
  snapshot     Json?       // 检查点快照 v2（形状与回溯语义见 1.3）
  messages     Message[]
}

model GenerationRequest {
  id             String   @id              // generationId，也是幂等键
  chapter_id     String
  status         String                    // pending | completed | failed
  stage          String   @default("reserved")
  output_snapshot Json?                    // 字段实现名 outputSnapshot；服务端私有
  retryable      Boolean  @default(true)
  safe_error     String?
  stage_updated_at DateTime
  attempt        Int      @default(1)
  lease_expires_at DateTime?
  narrator_message_id String
  result_meta    Json?
}

model Message {
  id          String @id
  chapter_id  String
  role        String   // player | narrator
  content     String
  scale       String   // scene | era | epoch   （发送时的尺度档）
  variants    Json?    // 异文候选 [{content, chosen}]
  meta        Json?    // 建议列表、揭示事件id、能力揭示信号、实体链接span等
  index       Int
  ability_events AbilityEvent[] // 以本消息为正文证据的能力沿革
}
```

> `Chapter` 是历史兼容的数据库名称，产品语义是**内部检查点窗口**。游戏内没有玩家可见的章节、章号、章题或“结束本章”操作；新窗口 `title=null`，顶部标题固定来自 `World.name + RealityState.currentEra + ObserverState.timeLabel`。

- **连续读取**：state API 展平最近四个内部窗口，最多 80 条；只有当前 `settle_state=open` 且属于活动现实的消息可编辑。
- **时间与轻变化**：Narrator meta 的白名单补丁分别写入 `RealityState.currentEra`、`ObserverState.timeLabel` 与当前现实实体；任一非法引用使整个事务回滚。
- **自动整理**：重大变化或六轮兜底将 meta 标记 `settlementRequired`，状态机沿用 `settle_state` 幂等恢复。
- **追溯分叉**：只有 Creator 推翻既成历史时创建 RealityRewrite；源现实不写临时 player/Narrator 消息。结果消息标记为需要整理。
- **裁去/朱批/异文**：仅允许当前开放窗口；此前窗口和冻结现实由服务端统一返回 409。
- **陨灭终章与已成史（concluded）**：仅 Pantheon 世界可成史。玩家神位阶跌至 `fallen` 且当前窗口 `open` 时，`POST /api/worlds/[id]/conclude` 复用 settlement 操作租约（与叙事/整理/改写天然互斥）生成终章：写入 `meta.kind="finale"`、`scale=epoch` 的史官终章消息与终章编年史，CAS 将 `status: playing→concluded` 并把当前窗口置 `settled`；LLM 或事务失败时世界保持 `playing`，可重试。concluded 后现实树管理接口返回 409「此界已成史」，窗口 `settled` 只读锁使正文编辑同样被拒。

### 1.1 可恢复正文生成

`GenerationRequest.stage` 是普通叙事的 durable 断点，单向流转：

```text
reserved → context_ready → generating → output_stored → applying → completed
```

- 完整 LLM 输出先保存为私有 `output_snapshot = { prose, parsedMeta, generatedAt, contractVersion }`，再进入应用事务。
- 在 `output_stored` 或 `applying` 失败时，重试直接复用快照，不再次调用 Narrator。
- `retryable / safe_error / stage_updated_at` 供 state API 恢复失败步骤；原始错误、租约和私有快照不进入公开 DTO 或存档。
- 消息、动态和事件记录使用 generationId 派生的稳定 ID，保证 owner 重放和断线恢复不重复写入。

### 1.2 持续事件与世界动态

```prisma
model WorldEvent {
  id                 String   @id            // 服务端按 generationId 稳定派生
  timeline_id        String
  kind               String                 // war | conspiracy | disaster | ...
  title              String
  summary            String
  phase              String                 // emerging | developing | escalating | resolved
  visibility         String                 // public | player_known | hidden
  participant_ids    String[]
  origin_message_id  String
  origin_activity_id String?
  latest_message_id  String
  parent_event_id    String?
  created_at         DateTime
  updated_at         DateTime
  resolved_at        DateTime?
}

model WorldActivity {
  id                String   @id             // 服务端按 generationId 与项序号稳定派生
  timeline_id       String
  event_id          String?
  record_type       String                  // action | activity | event_progress
  kind              String
  text              String
  visibility        String                  // public | player_known | hidden
  actor_id          String?
  target_ids        String[]
  subject_ids       String[]
  source_message_id String
  era_label         String
  time_label        String
  created_at        DateTime
}
```

- `WorldEvent` 保存战争、阴谋、灾难等跨轮事件链；`WorldActivity` 统一保存对象轻行动、一次性动态和事件进展。
- `event_progress` 通过 `event_id` 归入发展链；事件变化整项原子，行动和普通动态逐项过滤。
- `ObserverState.focusedEventId` 只能指向活动 Timeline 中未解决的事件；关注仅提高后续 Context Builder 权重，不触发 LLM、不切换场景。事件解决后由服务端清空。
- Timeline 删除随外键级联删除其事件和动态；事件引用使用 `onDelete: SetNull`，因此事件脱钩时动态 `event_id` 置空，父事件删除时子事件 `parent_event_id` 置空。世界或现实子树删除不会留下孤立记录。
- 普通 Narrator 应用已实现稳定 ID 与重放幂等；Phase 4 的世界整理、现实克隆和存档导入同样必须复用该规则。

### 1.3 检查点快照 v2 与万神殿回溯

章末结算的 snapshot 步骤把整个世界物化进 `Chapter.snapshot`：

```json
{
  "snapshotVersion": 2,
  "gods": [], "entities": [], "abilities": [],
  "entityRelations": [], "worldEvents": [],
  "omens": [], "canonEvents": [],
  "temporal": { "realityState": {}, "observerState": {} },
  "pendingSettlement": {}
}
```

- v2 在旧快照基础上补齐能力、实体关系、世界事件、征兆、将临之事与时间态（`realityState`/`observerState`），使万神殿检查点回溯可完整还原；`entities` 内嵌栏目，`omens` 只存 `{godId, text, kind, consumed, createdAt}`——刻意不存征兆行 ID（克隆不预映射征兆 ID）。既有读者只取 `pendingSettlement`。
- 检查点列表接口只认 `snapshot.snapshotVersion = 2` 的已结算章；旧快照缺 `canonEvents` 字段时回溯跳过将临之事回滚（与既有行为一致）。
- 万神殿回溯（checkpoint fork）在世界 `switch` 操作租约 + 可串行化事务内执行：克隆当前时间线 → 截断检查点之后的历史 → 按快照还原 → 绑定合成 `RealityRewrite` 行并切换活动现实；幂等键可安全重放。

## 3. 百科（Codex）= 结构化状态卡

```prisma
model Entity {
  id           String @id
  timeline_id  String
  type         String   // faction | character | race | place | artifact | cult
  name         String
  aliases      String[]                 // 本名+别名+称号（实体索引的匹配源）
  emblem_seed  String                   // 程序纹章种子（名字哈希）
  image_url    String?                  // 玩家上传；预留 AI 生图
  starred      Boolean @default(false)  // 玩家标星→永不降档
  is_chosen    Boolean @default(false)  // 神选者→永不降档/压缩
  is_major_character Boolean @default(false) // 创世 6–12 位主要人物，后续人物可晋升
  race_id      String?                  // character 的主种族；旧人物可为空
  heat         String  @default("active") // active | dormant
  scene_presence Boolean @default(false) // 当前在场（强制注入）
  summary      String                   // 摘要卡内容（dormant 时的全部）
  sections     EntitySection[]
  abilities    Ability[]                // 种族模板或人物个体能力
  memberships  EntityMembership[]       // 人物—势力多对多关系
  locked_paths String[]                 // player_locked 字段路径
}

model EntitySection {     // 栏目 = 迷雾与更新的最小粒度
  id         String @id
  entity_id  String
  key        String   // overview|territory|faith|lifespan|beliefs|... 按类型模板
  content    Json
  revealed   Boolean @default(true)   // false → 「传闻/经卷残缺」样式
  rumor_text String?                  // 未揭示时展示的传闻（可为误导）
  player_locked Boolean @default(false)
}
```

- 六类实体的栏目模板在代码中以常量定义（01 篇 9.1 表）；`EntitySection.key` 受模板约束。
- 人物类固有栏目含 `lifespan {born_year, expected, dead?}`、`faith_history[]`、`voice`。
- 实体专属编年史不落此表——由 ChronicleEntry 反查（见下）。
- `EntityMembership { character_id, faction_id, role, is_primary }` 取代势力关键人物的纯姓名运行时关联；同一人物可属于多个势力。
- 新世界以稳定引用物化 6–12 位主要人物；旧世界不自动回填 `is_major_character`、`race_id` 或成员关系。

## 4. 结构化能力与沿革

```prisma
model Ability {
  id              String @id
  timeline_id     String
  entity_id       String?  // race 或 character
  god_id          String?  // player/major god
  source_ability_id String? // 人物技艺掌握或先天覆写所指的种族模板
  name            String
  kind            String   // racial_innate | racial_tradition | personal | divine
  effect          String
  trigger         String
  cost             String
  limitations      String
  mastery          String   // unawakened | novice | adept | expert | master
  state            String   // normal | enhanced | impaired | sealed | lost | deprecated
  visibility       String   // known | rumored | hidden
  rumor_text       String?
  bloodline_justification String?
  locked_fields    String[]
  version          Int      // 乐观并发控制
  events           AbilityEvent[]
}

model AbilityEvent {
  id          String @id
  ability_id  String
  chapter_id  String
  message_id  String?  // 最直接的正文证据
  type        String    // awakened | learned | improved | mutated | impaired |
                       // sealed | restored | lost | revealed | deprecated
  before      Json?
  after       Json?
  evidence    String
  scale       String    // 证据消息自己的 scene | era | epoch
  dedupe_key  String @unique
  created_at  DateTime
}

model EntityMembership {
  id           String @id
  character_id String
  faction_id   String
  role         String
  is_primary   Boolean
  @@unique([character_id, faction_id])
}
```

约束与解析语义：

- `entity_id` 与 `god_id` 必须恰有一个非空，且所有者、来源与能力必须同属一条时间线。
- 种族模板只能是 `racial_innate` / `racial_tradition`；人物来源记录必须指向同类型、同时间线的种族模板；个人技能只属于人物，神权只属于神明。
- 人物有效能力 = 主种族当前可用先天能力 + 人物对先天来源的覆写 + 明确掌握的族群技艺 + 个人技能。族群技艺绝不因 `race_id` 自动生效。
- `unawakened`、`sealed`、`lost`、`deprecated` 不进入正常可用集合；`impaired` 仍可用但携带受损限制。掌握程度只影响叙事，不换算数值。
- 能力失去或废弃时保留记录与事件沿革；`dedupe_key` 使章末断点续跑不会重复演化。
- 玩家投影中，`known` 返回完整字段；`rumored` 只返回传闻安全摘要；`hidden` 整项过滤。私有存档导出例外：必须保留完整数据。

## 5. 编年史

```prisma
model ChronicleEntry {
  id          String @id
  timeline_id String
  chapter_index Int
  year_label  String    // 纪年文本（主题卡的纪年体系）
  text        String    // 史官笔法 2-3 句
  entity_ids  String[]  // 涉及实体（实体专属编年史 = 按此筛选）
  god_ids     String[]
  revealed    Boolean   // false = 诸神隐藏行动（幕后大事记）
  revealed_at_chapter Int?   // 「于第N章揭晓」
  source      String    // narrative | pantheon(诸神回合) | manual
}
```

- **隐藏大事记**与可见编年史同表（`revealed` 区分），揭示即翻转并记录揭晓章。
- 待织入征兆队列：`OmenQueue { id, timeline_id, god_id, text, kind, consumed }`。`kind ∈ {omen, proactive}`：`omen` 是暗地征兆；`proactive` 是诸神主动事件——万神殿结算里神明直接针对玩家神的行动（托梦/遣使/神迹挑战/召集神议）以 `openingHook` 原文分型入队。Context Builder 每轮至多租借 1 条 proactive（FIFO）+ 2 条普通征兆注入叙事，输出后标记消费；proactive 在叙事者提示词渲染为正面登台块（点名神明，禁止降格为暗示）。

### 5.1 将临之事（CanonEvent）

作者侧未来候选事件（时间一致世界生成设计稿 §5.3/§8 阶段3）。表名 `canon_events`：

```prisma
model CanonEvent {
  id            String @id
  timeline_id   String
  ref           String     // 卡组稳定 ref；@@unique([timeline_id, ref])
  title         String
  time_label    String
  ordinal       Int        // 时间次序；@@unique([timeline_id, ordinal])
  epoch         String     // 默认 "future"
  summary       String
  participant_refs String[]  // 卡组稳定 ref，绝不落库 DB id
  prerequisites Json       // 前置条件（含 prior_event_occurred 引用更早将临之事的 ref）
  blockers      Json?
  expected_consequences Json?
  status        String     // pending | eligible | altered | cancelled | occurred
  visibility    String     // 默认 author_only
  divergence_note String?  // altered/cancelled 的改道说明（作者侧）
  occurred_chapter_index Int?
}
```

- **物化**：创世卡组的 `canonEvents`（future 档 3–5 条）在开局时逐条落库；参与者与条件引用保持卡组稳定 ref 原样入库。旧草稿与既有卡组没有该键，开局流程不变。
- **状态机**：由章末结算维护，合法迁移 `pending→eligible/altered/cancelled/occurred`、`eligible→occurred/altered/cancelled`；非法迁移静默跳过，这同时使结算断点重跑幂等。`altered/cancelled` 写 `divergence_note`，`occurred` 写 `occurred_chapter_index`。
- **玩家侧半透出**：`eligible` 且结算给出 rumor 时，以稳定 ID `canon-rumor:<chapterId>:<ref>` 落一条 `public` 传闻 `WorldActivity`（幂等守卫），经世界动态机制流入叙事上下文与动态抽屉——这是玩家侧可见的全部；author_only 字段永不进入叙事者提示词。章末结算提示词则以 author-only 块回喂 `pending/eligible` 两档（禁止逐字引用；已裁决档不再消耗上下文预算）。
- **刻意不做**（导演内核接手前的边界）：`occurred` 不自动创建 `WorldEvent`——事件经正文与结算动态机制自然成真；`altered/cancelled` 不产传闻。
- **克隆/回溯/导入零重映射**：行内引用全部是卡组稳定 ref，图克隆逐字段照抄（新 id 由 cuid 生成）；存档导入只校验 `timeline_id` 归属声明，不做记录级引用解析。

## 8. 导出格式

- **存档 JSON v4**：`{version: 4, exportedAt, world, iconCreditsMarkdown}`。每条时间线完整导出人物 `race_id`、能力、成员关系、能力沿革、实体关系、`worldEvents`、`worldActivities`、征兆（含 `kind`）、`canonEvents`、`iconAssignments` 与 `observerState.focusedEventId`；世界级导出 `iconTheme`，剔除 `materialArchiveError`。顶层 `iconCreditsMarkdown` 是按世界实际使用的图标（entity/god/ability/event 四类分配 + 主题）汇编的致谢文本。私有导出保留 hidden 内容。
- **导入只认 v4**：`version !== 4` 一律 400「存档版本不受支持：仅接受 version 4」，不再接受 v1–v3 或做事件图回填。`iconCreditsMarkdown` 接受但忽略，再次导出时重新生成。导入先预生成所有新 ID，再按世界 → 时间线 → 章节/实体/关系/栏目/神/消息 → 能力/成员关系/能力事件 → 编年史/征兆/将临之事 → 改写 → 事件 → 动态 → 图标分配的顺序写入并修复引用；将临之事只校验归属声明（引用全部是卡组稳定 ref），征兆 `kind` 缺省按 `omen` 读取。
- **私有字段边界**：archive 不包含 GenerationRequest 租约、`outputSnapshot`、原始 error 或世界操作 owner 信息；旧消息不因升级重新生成。
- **旧世界策略**：不迁移、不回填、不一键补齐主要人物或能力。旧世界空能力集合可以继续游玩，后续仅在剧情明确展示且有证据时渐进建档。
- **《创世史》**：按连续正文与内部检查点摘要拼装，不向读者制造游戏章节操作；Markdown 直出，EPUB 书名《创世史·〈世界名〉》。
- **模板**（M3）：世界卡组 + 世界书条目（不含对局正文/编年史），发布到 `Template` 表（含 `moderation_state` 预留字段）。

## 10. 图标系统

世界级图标主题落 `World`（迁移 `20260726143000_world_icon_system`）：`icon_theme Json?`（主题：图标族偏好 + 类别映射 + `lockedAssignments` 世界级锁定）、`icon_theme_revision Int`（版次）、`icon_theme_operation_key String?`（主题生成幂等键）。对象级分配单独成表：

```prisma
model IconAssignment {        // 表名 icon_assignments
  id            String @id
  timeline_id   String        // Timeline 删除级联
  subject_type  String        // entity | god | ability | event
  subject_id    String
  token         String        // 语义图标 token（如 event.conflict）
  source        String        // generated | derived | player
  player_locked Boolean       // 玩家钉选：自动分配不得覆盖
  @@unique([timeline_id, subject_type, subject_id])
}
```

- **source 语义**：LLM 给出 iconConcept 时自动分配为 `generated`，否则按类别派生为 `derived`；玩家手动改选写 `player` 并置 `player_locked=true`（token 必须存在于图标目录）。恢复默认回到 `generated/derived` 且解除锁定；自动分配遇到 `player_locked` 行直接跳过。
- **解析顺序**（resolver）：行级分配 token → 主题 `lockedAssignments`（`<subjectType>.<subjectId>` 键或 token 键）→ 主题类别映射（entityTypes/abilityKinds/eventKinds）→ 各 `subject_type` 默认 token；再按主题图标族偏好取具体图标，缺失时回退 phosphor 族。
- **克隆**：现实分叉时 `subject_id` 按实体/神/能力/事件四张映射表重映射；无法映射的分配记日志后跳过，不阻断分叉。
- **存档**：v4 每条时间线导出 `iconAssignments`，世界级导出 `iconTheme`；顶层 `iconCreditsMarkdown` 由四类分配 + 主题聚合出实际使用的图标致谢（导入忽略，再导出重算）。
