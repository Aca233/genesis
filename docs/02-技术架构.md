# 02 · 技术架构

## 0. Creator Mode 架构增补

- `World.mode` 是服务端唯一权限来源，创建后不可修改；不得从 query/body 推断全知权限。
- 活动状态由 `World.activeTimelineId` 指向。所有 chat/settlement/rewrite/switch 在预留与提交阶段都校验活动现实，旧分支写入返回 409。
- `World.operationKind/token/leaseExpiresAt` 构成 5 分钟 CAS 租约；流式叙事、长结算和改写按租期三分之一续租，失败即停止后续写入，释放必须匹配 kind+token。
- 改写 runner 是可恢复状态机：`planning → applying(branching) → narrating → completed/failed`。任务租约与世界租约并用，幂等键保证重放不重复克隆；应用事务成功、叙事失败时只重试叙事。
- 改写核心事务使用 Serializable：重新读取活动源现实 → 完整克隆图 → 重映射计划 → 确定性应用 → 建结果章节 → CAS 切换活动现实。任何计划/引用错误整体回滚。
- `RealityViewer` 由 `World.mode + active Timeline.observerState` 计算。limited/Pantheon 在服务端删去秘密；omniscient 返回完整数据并保留 `worldVisible`，前端只负责标注而不承担保密。
- v3 import 在写入前验证现实图，按 world/timeline → owned rows → rewrites → parent/result/active 修复顺序导入；操作租约、任务 token 和 provider error 永不导出。

## 3. LLM Gateway（BYOK 核心）

### 3.1 双槽位

```ts
type ModelSlot = {
  provider: 'openai-compatible' | 'anthropic' | 'gemini'
  baseUrl: string        // 中转站关键：完全自定义
  apiKeyEncrypted: string
  model: string
  temperature?: number
  maxTokens?: number
}
// settings: { narrative: ModelSlot; backstage?: ModelSlot }  // 幕后缺省回落叙事槽
```

### 3.2 安全与健壮性

- Key 用 AES-256-GCM 加密落库，密钥来自环境变量 `SECRET_KEY`（.env，不入库不入代码）。
- 服务端代理转发，浏览器永不见 Key。
- 统一重试策略：网络错误/429 指数退避 ×3；结构化输出 Zod 校验失败 → 携错误重问 ×2。
- 所有调用记录 `llm_calls` 日志表（任务类型、耗时、token 用量估算），便于玩家排查中转站问题。

### 3.3 任务→槽位路由

| 任务 | 槽位 | 输出形式 |
|---|---|---|
| 世界生成 / 卡片重掷 | 叙事槽 | 结构化 JSON |
| 正文叙事（含行动建议） | 叙事槽 | 流式文本 + 尾部 JSON 块 |
| 诸神回合（每主神一次） | 幕后槽 | 结构化 JSON |
| 状态抽取 / 编年史压缩 | 幕后槽 | 结构化 JSON |
| 查探裁决（占卜等，随正文） | 叙事槽 | 随正文 |

## 4. 核心流水线

### 4.1 叙事生成（每次玩家发送）

```
玩家输入 + 当前尺度档
  → Context Builder:
      系统提示（风格卡+宇宙论+融合公理+玩家神卡+尺度文体规则）
      + 检索注入（本轮命中的实体卡/世界书条目/相关编年史，见 4.3）
      + 待织入征兆（未消费的 omen 队列，标注「不着痕迹地织入」）
      + 近期正文窗口（滑动，按 token 预算裁剪）
  → 叙事槽 SSE 流式输出正文
  → 尾部结构化块：{ suggestions: string[], chapterBreakHint?: boolean,
                    revealedEvents?: id[], enrolledChosen?: {...}[] }
  → 服务端后处理：实体名 → 微光链接标记；揭示事件补录编年史
```

### 4.2 翻章结算（Pantheon Engine）

```
POST /api/chapters/:id/settle   （SSE 推进度给前端演出）
  1. 诸神回合：for each 主神 → 幕后槽调用 → {action, omen, agenda_update, relations_update}
       行动入隐藏大事记；omen 入待织入队列；增量更新神卡
  2. 状态抽取：本章正文分片 → 幕后槽 → 实体增量（建卡/更新/关系/热度信号）
       应用时跳过 player_locked 字段
  3. 编年史压缩：本章正文 → 2-3 句纪年条目 + 章末小结
  4. 热度衰减 + 章快照落库
失败恢复：每步幂等、断点续跑（结算状态机存 chapter.settle_state）
```

### 4.3 检索注入（关键词主 + 向量可选）

- **实体索引**：每个百科条目维护 `names[]`（本名+别名+称号）；对最近 N 轮正文与玩家输入做 Aho-Corasick 多模式匹配 → 命中实体的状态卡入上下文。
- **在场实体**：当前场景登场中的实体（由抽取器维护 `scene_presence`）强制注入。
- **世界书条目**：按 ST 原生 keys 触发规则匹配注入。
- **编年史**：命中实体的专属编年史取最近/最重要条目。
- **可选向量增强**：设置中若配置 embedding 端点，则对编年史与设定集做语义补充检索；未配置系统完全可用（已定：BYOK 下不依赖 embedding）。
- 注入总量按 token 预算分级裁剪：在场实体卡 > 神卡 > 世界书 > 编年史。

## 7. 双模式与现实改写架构

### 7.1 不变量与投影

`World.mode` 是持久化且不可变的 `pantheon | creator`。所有创世卡、开局物化、Narrator、章末结算、状态 API、导入和现实应用都在服务端复核模式不变量；Creator 现实不得含玩家神。

状态读取先构造服务端 `RealityViewer`：Pantheon 只能使用玩家安全投影；Creator 的 `omniscient` 返回作者侧完整内容但保留 `worldVisible/visibility` 元数据，`limited` 则在服务器删除秘密。query 参数不能提升 Pantheon 权限。

### 7.2 世界级操作租约

`World` 上保存 `operationKind / operationToken / operationLeaseExpiresAt`，使用 PostgreSQL `updateMany` CAS 串行化 `chat / settlement / rewrite / switch`。租约默认五分钟，长任务按三分之一周期续租；每个大写入阶段前核验 token 与未过期所有权，续租失败立即停止后续写入，`finally` 只按匹配 token 释放。冻结现实守卫与租约守卫同时生效。

### 7.3 幂等现实改写

改写 API 先以 `idempotencyKey` 建立 `RealityRewrite`，runner 使用可续期任务租约恢复 `planning → cloning → applying → completed`。Planner 只输出 Zod 白名单 `RewritePlan`；clone 在同一事务复制完整时间线图并重映射 JSON 内嵌引用；apply 按固定阶段执行并在最终做跨引用与 Creator 无玩家神校验。结果完成后 CAS 切换 `activeTimelineId`，SSE 可重连读取事件；重复请求返回同一任务，不重复分叉。

### 7.4 现实树与观察者

现实树验证唯一根、同世界父子、无环、活动节点存在及 rewrite fork 一致性。切换、撤销、重命名和删除子树由 Creator-only API 执行；删除在事务中递归移除冻结子树，根与活动现实不可删除。

`observerState` 随时间线克隆，记录 viewpoint、focus 与 activeAvatarId。Observer API 只允许引用活动现实内对象；化身是 `Entity(type=character, isCreatorAvatar=true)`，进入/退出只改观察状态，收回令实体 dormant 并保留历史。

### 7.5 存档边界

私有导出使用 version 3，包含模式、所有现实、观察状态、化身与改写记录，但永不序列化世界操作 token、任务 lease token 或可能含 provider 细节的 error。导入先完整验证图，再按依赖顺序写入并修复 parent/fork/result/active ID；v1/v2 按 Pantheon 单根现实兼容。

## 8. 厂商 Prompt Cache

高价值模型请求由业务层按 `global → world → dynamic` 标记消息稳定性，`src/lib/llm/cache.ts` 只计算第一条动态消息之前的连续稳定前缀。稳定前缀不少于 4,000 字符时，规划器才生成仅含 SHA-256 摘要的缓存键；Prompt、神谕、正文、世界书及隐藏设定不会写入调用日志。

数据流如下：

```
业务请求（稳定性标记 + 低基数 namespace）
  → Cache Planner（连续前缀、双断点、哈希键）
  → Provider Adapter
      OpenAI-compatible: prompt_cache_key + 流式 usage
      Anthropic: global/world 最多两个 ephemeral 断点
      Gemini: 仅使用厂商隐式缓存
  → Gateway 截留 Usage
  → llm_calls（Token 数与兼容回退标记）
  → /api/settings/cache-stats
  → 香炉统计卡
```

OpenAI 兼容中转站若明确拒绝 `stream_options` 或 `prompt_cache_key`，Adapter 在同一 attempt 内只去除对应字段重试一次，并按规范化端点与模型记忆能力；认证、限流、服务错误和已中止请求不会触发此回退。Anthropic 对明确拒绝 `cache_control`/数组 System 的端点采用同样的一次去参回退。该机制不会与 Gateway 的网络重试相乘。

缓存只复用厂商侧输入前缀，不缓存、存储或复用模型答案。Usage 统一记录输入、输出、缓存读取和缓存写入 Token；厂商未返回字段时保留 `NULL`，统计命中率不会把未知值当作 0%。
