# 02 · 技术架构

## 1. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | **Next.js 15+（App Router）单体应用** | TS 全栈已定；前后端一体，小圈子规模无需拆服务；SSE 流式在 Route Handler 原生支持 |
| 语言 | TypeScript（strict） | 已定 |
| 数据库 | **PostgreSQL 16 + Prisma ORM** | 关系模型复杂（实体/关系/章节/分叉树）；JSONB 存卡片弹性字段；本机 Docker 起，VPS 平移 |
| 状态/数据流 | TanStack Query + Zustand（轻） | 服务器状态与本地 UI 状态分离 |
| 样式 | Tailwind CSS v4 + 自建组件体系 | 已定；羊皮古卷主题走 CSS 变量双模式（日卷/烛光） |
| 动效 | Framer Motion（motion） | 已定；仪式演出与面板物理感 |
| 星图/纹章 | SVG（D3-force 布局星图；名字哈希→SVG 纹章生成器） | 已定自绘 |
| LLM 接入 | 自写轻量 Provider 适配层（OpenAI 兼容 / Anthropic / Gemini 三协议） | BYOK 多协议+中转站兼容是硬需求，不引 LangChain 级重依赖 |
| 校验 | Zod（所有 LLM 结构化输出、所有 API 边界） | LLM 输出不可信，schema 校验失败自动重试 |
| 部署 | 本机 `next dev`/Docker Desktop 先行；VPS 用 Docker Compose（app + postgres + caddy） | 已定 |

> 具体依赖版本在动代码前以 context7 查最新文档为准，方案不锁小版本。

## 3. LLM Gateway（BYOK 核心）

### 3.1 双槽位

```ts
type ModelSlot = {
  provider: 'openai-compatible' | 'anthropic' | 'gemini'
  baseUrl: string        // 中转站关键：完全自定义
  apiKeyEncrypted: string
  model: string
  temperature?: number
  maxTokens?: number
}
// settings: { narrative: ModelSlot; backstage?: ModelSlot }  // 幕后缺省回落叙事槽
```

### 3.2 安全与健壮性

- Key 用 AES-256-GCM 加密落库，密钥来自环境变量 `SECRET_KEY`（.env，不入库不入代码）。
- 服务端代理转发，浏览器永不见 Key。
- 统一重试策略：网络错误/429 指数退避 ×3；结构化输出 Zod 校验失败 → 携错误重问 ×2。
- 所有调用记录 `llm_calls` 日志表（任务类型、耗时、token 用量估算），便于玩家排查中转站问题。

### 3.3 任务→槽位路由

| 任务 | 槽位 | 输出形式 |
|---|---|---|
| 世界生成 / 卡片重掷 | 叙事槽 | 结构化 JSON |
| 正文叙事（含行动建议） | 叙事槽 | 流式文本 + 尾部 JSON 块 |
| 诸神回合（每主神一次） | 幕后槽 | 结构化 JSON |
| 状态抽取 / 编年史压缩 | 幕后槽 | 结构化 JSON |
| 查探裁决（占卜等，随正文） | 叙事槽 | 随正文 |

## 4. 核心流水线

### 4.1 叙事生成（每次玩家发送）

```
玩家输入 + 当前尺度档
  → Context Builder:
      系统提示（风格卡+宇宙论+融合公理+玩家神卡+尺度文体规则）
      + 检索注入（本轮命中的实体卡/世界书条目/相关编年史，见 4.3）
      + 待织入征兆（未消费的 omen 队列，标注「不着痕迹地织入」）
      + 近期正文窗口（滑动，按 token 预算裁剪）
  → 叙事槽 SSE 流式输出正文
  → 尾部结构化块：{ suggestions: string[], chapterBreakHint?: boolean,
                    revealedEvents?: id[], enrolledChosen?: {...}[] }
  → 服务端后处理：实体名 → 微光链接标记；揭示事件补录编年史
```

### 4.2 翻章结算（Pantheon Engine）

```
POST /api/chapters/:id/settle   （SSE 推进度给前端演出）
  1. 诸神回合：for each 主神 → 幕后槽调用 → {action, omen, agenda_update, relations_update}
       行动入隐藏大事记；omen 入待织入队列；增量更新神卡
  2. 状态抽取：本章正文分片 → 幕后槽 → 实体增量（建卡/更新/关系/热度信号）
       应用时跳过 player_locked 字段
  3. 编年史压缩：本章正文 → 2-3 句纪年条目 + 章末小结
  4. 热度衰减 + 章快照落库
失败恢复：每步幂等、断点续跑（结算状态机存 chapter.settle_state）
```

### 4.3 检索注入（关键词主 + 向量可选）

- **实体索引**：每个百科条目维护 `names[]`（本名+别名+称号）；对最近 N 轮正文与玩家输入做 Aho-Corasick 多模式匹配 → 命中实体的状态卡入上下文。
- **在场实体**：当前场景登场中的实体（由抽取器维护 `scene_presence`）强制注入。
- **世界书条目**：按 ST 原生 keys 触发规则匹配注入。
- **编年史**：命中实体的专属编年史取最近/最重要条目。
- **可选向量增强**：设置中若配置 embedding 端点，则对编年史与设定集做语义补充检索；未配置系统完全可用（已定：BYOK 下不依赖 embedding）。
- 注入总量按 token 预算分级裁剪：在场实体卡 > 神卡 > 世界书 > 编年史。

## 5. 前端结构

```
app/
  page.tsx                 首屏（一句话输入）
  genesis/[draftId]/       卡片编辑器
  play/[worldId]/          主游玩界面
    ─ 书页正文流（SSE 渲染 + 实体链接 + 异文/朱批/裁去/续笔）
    ─ 输入区（朴素输入框 + 书签丝带切换器 + 悬浮建议）
    ─ 右缘符文列 + 抽屉（五页签 + 香炉）
    ─ 仪式演出层（创世/岁月流转/陨落，全屏 overlay）
```

- 正文流虚拟化渲染（几百章不卡）；实体链接在服务端标记、客户端渲染为悬停快览组件。

## 6. 部署

### 6.1 本机（M1 即用）

```bash
docker compose up -d postgres   # 仅数据库进容器
pnpm dev                        # Next.js 本机跑
```

### 6.2 VPS（预留）

`docker-compose.prod.yml`：app（standalone 构建）+ postgres（volume 持久化）+ caddy（自动 HTTPS）。环境变量只多 `DATABASE_URL`/`SECRET_KEY`/域名。单用户模式下先加一层 Caddy basic-auth 即可给朋友用；Discord OAuth 属后续（表已预留 user_id）。
